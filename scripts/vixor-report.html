ملخص تنفيذي
تطبيق VIXOR هو تيرمنال تداول ذكي مبني بتقنية React + TanStack Start، يعمل كتطبيق Telegram Web App. يحتوي التطبيق على 37 صفحة ومكون رئيسي موزعة على نظام توجيه معقد. تم بناء الواجهة بالكامل باستخدام inline styles مع نظام CSS Variables لتوحيد الالوان، لكن بدون استخدام مكتبة مكونات موحدة او نظام تصميم منظم.
يعتمد التطبيق على عدد محدود من المكونات المشتركة المصدرة من PageLayout.tsx الذي يوفر حوالي 15 مكون فرعي (StatsRow, Badge, DataRow, EmptyState, ScrollArea, وغيرها). لكن معظم الصفحات تعيد بناء عناصر واجهة المستخدم من الصفر داخل كل ملف بدلا من استخدام هذه المكونات المشتركة، مما ادى الى تضخم كبير في حجم الملفات وعدم تناسق بصري بين الصفحات.

الفصل السادس
المشاكل المشتركة بين كل الصفحات
1. وباء Inline Styles
95% من التنسيق يتم عبر inline styles. هذا يعني ان اي تعديل تصميمي يتطلب تعديل كل ملف على حدة. الحل هو بناء نظام مكونات موحد باستخدام Tailwind CSS classes مع CSS Variables. نمط `${"var(--color-border)"}` يجب ان يستبدل بـ className مباشر.
2. ملفات ضخمة تحتاج تقسيم
10 ملفات تتجاوز 800 سطر و4 ملفات تتجاوز 2000 سطر. هذا يجعل الصيانة والتطوير بطيئين جدا ويمنع المراجعة الفعالة. كل ملف يجب ان لا يتجاوز 300-400 سطر كحد اقصى.
3. غياب انواع TypeScript
معظم الصفحات تستخدم any type للبيانات المستلمة من السيرفر. هذا يلغي فوائد TypeScript في اكتشاف الاخطاء مبكرا. يجب تعريف واجهات صارمة لكل نوع بيانات وربطها بالـ Supabase types.
4. عدم تناسق جلب البيانات
معظم الصفحات تستخدم useStableServerFn + useQuery (النمط الصحيح)، لكن 3 صفحات (activity-web3, admin/api-keys, arbitrage) تستخدم useState + useEffect مباشرة. هذا يسبب عدم تناسق في ادارة الحالة والتحميل والاخطاء.
5. توجيهات Next.js زائدة
ملفين يحتويان على "use client" وهو توجيه Next.js غير صالح لان التطبيق يستخدم TanStack Router. هذه التوجيهات يجب ازالتها فورا لانها قد تسبب ارتباكا.
6. غياب نظام مكونات موحد
رغم وجود PageLayout الذي يوفر 15 مكون فرعي، فان معظم الصفحات تعيد بناء الازرار والبطاقات والنماذج من الصفر. الحل هو بناء مكتبة مكونات VIXOR موحدة (Button, Card, Input, Select, Modal, Badge) تستخدم Tailwind classes وتتبع نظام التصميم بدقة.
VIXOR
هذا التقرير يغطي تحليلا شاملا لكل صفحة في تطبيق VIXOR. يُوصى بالبدء باعادة هيكلة الملفات الحرجة (التي تتجاوز 1000 سطر) ثم بناء نظام مكونات موحد قبل البدء في اعادة التصميم البصري.
