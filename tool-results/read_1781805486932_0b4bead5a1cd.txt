    13→## 1. الخلاصة التنفيذية (Executive Summary)
    14→
    15→QuantDinger هو منصة **Python/Flask + Vue + Postgres + Redis** تطرح نفسها كنظام "AI Quant OS" متكامل، صدر الإصدار V3.1.0 منه مع **AI Agent Gateway** و **MCP server** و **experiment orchestration layer**. الكود مفتوح المصدر برخصة Apache-2.0، ومكتوب بأسلوب احترافي (safe_exec sandbox ثلاثي الطبقات، capability-scoped tokens، circuit breaker للـ data sources، backtest engine بـ 5K LOC).
    16→
    17→VIXOR MASTER V2 هو تطبيق **TanStack Start (TypeScript/React SSR) + Supabase** يطالب بنفس الطموح (Bloomberg Professional للـ SMC/ICT traders)، لكنه **معاق تشغيلياً** بسبب:
    18→- 13 متغير بيئة مفقود محلياً (Vercel production لديه معظمها)
    19→- `deep-no-op Proxy` يبتلع كل أخطاء Supabase بصمت
    20→- `newsMap` بأخبار وهمية مدمجة في المحرك تعرض للمستخدم كأنها تحليل حقيقي
    21→- Layout محدود بـ `max-w-4xl` (896px) — ضيق جداً لتطبيق تداول
    22→- صفحات some features مكسورة (settings toggles, alert cron, dead code paths)
    23→
    24→### القرار الاستراتيجي
    25→
    26→**لا يمكن نقل كود QuantDinger مباشرة إلى VIXOR** لأن الـ stack مختلف جذرياً (Python/Flask vs TypeScript/TanStack). لكن **يمكن است corósticoage:**
    27→
    28→1. **الـ patterns المعمارية** (Agent Gateway، capability tokens، SSE progress، idempotency) — تُعاد كتابتها بـ TypeScript
    29→2. **الـ safe_exec sandbox** — يُعاد كتابته في Node.js `vm2` أو `isolated-vm` مع نفس الـ 3 طبقات
    30→3. **الـ backtest engine logic** — يُعاد كتابتها بـ TypeScript مع نفس الـ candle-path simulation
    31→4. **الـ strategy DSL** (`IndicatorStrategy` + `ScriptStrategy`) — يُعاد تصميمه لـ JavaScript/TypeScript
    32→5. **الـ circuit breaker + rate limiter + cache** — يُعاد كتابتها بـ TypeScript (سهلة)
    33→6. **الـ broker adapters** — تُعاد كتابتها لـ 4 exchanges أساسية (Binance, OKX, Bybit, Coinbase) — لا تحتاج ccxt
    34→7. **الـ multi-provider LLM service** — يُعاد كتابته بـ TypeScript (7 providers)
    35→8. **الـ multi-channel notifier** — يُعاد كتابته بـ TypeScript (Telegram + Email + Webhook)
    36→9. **الـ credential encryption** — يُستبدل بـ `crypto.createCipheriv` في Node.js
    37→10. **الـ experiment orchestration** — يُعاد كتابته بـ TypeScript

   213→#### 1.1 نقل `safe_exec` sandbox إلى TypeScript (P0)
   214→- **المصدر:** `audit/QuantDinger/backend_api_python/app/utils/safe_exec.py` (470 LOC)
   215→- **الهدف:** `src/shared/safe-exec/index.ts` + `validator.ts` + `runner.ts`
   216→- **الـ approach:**
   217→  - **Layer 1 (regex blacklist):** نقل مباشر، نفس الـ patterns بالضبط
   218→  - **Layer 2 (AST):** استخدام `@typescript-eslint/parser` أو `acorn` للـ AST walk، نفس الـ import whitelist (`numpy, pandas, math, json, datetime, time, collections, functools, itertools, statistics, decimal, fractions, operator, copy` — لكن بالـ JS equivalents)

   220→  - **Timeout:** `Promise.race` مع `setTimeout` + `worker_threads` للـ CPU-bound
   221→  - **Subprocess isolation:** `worker_threads` (أخف من `child_process`)
   222→- **الجهد:** 2-3 أيام
   223→- **الاستخدام في VIXOR:** تنفيذ استراتيجيات Python/JS المقدمة من المستخدم بأمان

   238→#### 1.3 نقل `credential_crypto` إلى Node.js `crypto` (P0)
   239→- **المصدر:** `audit/QuantDinger/backend_api_python/app/utils/credential_crypto.py` (50 LOC)
   240→- **الهدف:** `src/shared/crypto/credential-crypto.ts`
   241→- **الـ approach:**
   242→  ```typescript
   243→  import { createCipheriv, createDecipheriv, scryptSync, randomBytes } from "crypto";
   244→
   245→  const KEY = scryptSync(process.env.SECRET_KEY!, "vixor-salt", 32); // AES-256
   246→
   247→  export function encryptCredential(data: object): string {
   248→    const iv = randomBytes(16);
   249→    const cipher = createCipheriv("aes-256-gcm", KEY, iv);
   250→    const enc = Buffer.concat([cipher.update(JSON.stringify(data), "utf8"), cipher.final()]);
   251→    const tag = cipher.getAuthTag();
   252→    return Buffer.concat([iv, tag, enc]).toString("base64url");
   253→  }
   254→
   255→  export function decryptCredential<T>(token: string): T {
   256→    const buf = Buffer.from(token, "base64url");
   257→    const iv = buf.subarray(0, 16);
   258→    const tag = buf.subarray(16, 32);
   259→    const enc = buf.subarray(32);
   260→    const decipher = createDecipheriv("aes-256-gcm", KEY, iv);
   261→    decipher.setAuthTag(tag);
   262→    const dec = Buffer.concat([decipher.update(enc), decipher.final()]);
   263→    return JSON.parse(dec.toString("utf8"));
   264→  }
   265→  ```
   266→- **الجهد:** نصف يوم
   267→- **الاستخدام في VIXOR:** تشفير exchange API keys قبل تخزينها في Supabase

   641→### مخاطر عالية (High Risk)

   643→| # | المخاطرة | التخفيف |

   646→| 2 | **`isolated-vm` له native bindings** قد لا تعمل على Vercel serverless | استخدام `vm2` بدلاً منه (pure JS لكن أبطأ). أو تشغيل الـ strategy execution في worker منفصل. |

   880→## الملحق ب: مرجع سريع لأهم الـ patterns في QuantDinger
   881→
   882→### Pattern 1: Capability-class scoped tokens
   883→```
   884→R = Read (markets, prices, klines, strategies, jobs)
   885→W = Write (create strategies, edit settings)
   886→B = Backtest (queue backtests)
   887→N = Notify (trigger notifications)
   888→C = Calendar (read economic calendar)
   889→T = Trade (place orders — paper or live, gated by paper_only flag + AGENT_LIVE_TRADING_ENABLED)
   890→```
   891→
   892→### Pattern 2: SSE progress protocol
   893→```
   894→event: snapshot
   895→data: {"job_id":"...","status":"running","progress":45}
   896→
   897→event: progress
   898→data: {"seq":1,"ts":"...","data":{"phase":"backtesting","bar":45/200}}
   899→
   900→event: ping
   901→(15s keepalive)
   902→
   903→event: result
   904→data: {"status":"succeeded","result":{...}}
   905→```
   906→
   907→### Pattern 3: Idempotency-Key unique partial index
   908→```sql
   909→CREATE UNIQUE INDEX idx_agent_jobs_idem
   910→  ON qd_agent_jobs(agent_token_id, kind, idempotency_key)
   911→  WHERE idempotency_key IS NOT NULL;
   912→```
   913→
   914→### Pattern 4: Three-layer safe execution
   915→```
   916→Layer 1: Regex blacklist (os.system, subprocess, __import__, eval, exec, ...)
   917→Layer 2: AST walk (whitelist imports, reject dangerous calls)
   918→Layer 3: Restricted __builtins__ (whitelist functions only)
   919→+ Timeout (SIGALRM on Unix, threading.Timer + ctypes on Windows)
   920→+ Optional subprocess isolation (multiprocessing.Process)
   921→```
   922→
   923→### Pattern 5: Candle-path simulation
   924→```
   925→Bullish bar (close > open): O → L → H → C (dip then rally)
   926→Bearish bar (close < open): O → H → L → C (rally then dip)
   927→Doji (close ≈ open): O → H → L → C (worst case)
   928→```
   929→This lets SL/TP trigger intra-bar with realistic ordering.
   930→
   931→### Pattern 6: Circuit breaker state machine
   932→```
   933→CLOSED → (failures ≥ threshold) → OPEN
   934→OPEN → (after cooldown) → HALF_OPEN
   935→HALF_OPEN → (success) → CLOSED
   936→HALF_OPEN → (failure) → OPEN
   937→```
   938→
   939→### Pattern 7: SaaS-mode issuance-time guard
   940→```python
   941→if DEPLOYMENT_MODE in {'saas','shared','hosted','multitenant'}:
   942→    if 'T' in scopes:
   943→        abort(403, "T-scope not allowed in SaaS mode")
   944→    paper_only = True  # force-pin regardless of payload
   945→```
