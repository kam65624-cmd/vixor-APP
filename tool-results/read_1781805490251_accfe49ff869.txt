    13→    13→## 1. الخلاصة التنفيذية (Executive Summary)
    14→    14→
    15→    15→QuantDinger هو منصة **Python/Flask + Vue + Postgres + Redis** تطرح نفسها كنظام "AI Quant OS" متكامل، صدر الإصدار V3.1.0 منه مع **AI Agent Gateway** و **MCP server** و **experiment orchestration layer**. الكود مفتوح المصدر برخصة Apache-2.0، ومكتوب بأسلوب احترافي (safe_exec sandbox ثلاثي الطبقات، capability-scoped tokens، circuit breaker للـ data sources، backtest engine بـ 5K LOC).
    16→    16→
    17→    17→VIXOR MASTER V2 هو تطبيق **TanStack Start (TypeScript/React SSR) + Supabase** يطالب بنفس الطموح (Bloomberg Professional للـ SMC/ICT traders)، لكنه **معاق تشغيلياً** بسبب:
    18→    18→- 13 متغير بيئة مفقود محلياً (Vercel production لديه معظمها)
    19→    19→- `deep-no-op Proxy` يبتلع كل أخطاء Supabase بصمت
    20→    20→- `newsMap` بأخبار وهمية مدمجة في المحرك تعرض للمستخدم كأنها تحليل حقيقي
    21→    21→- Layout محدود بـ `max-w-4xl` (896px) — ضيق جداً لتطبيق تداول
    22→    22→- صفحات some features مكسورة (settings toggles, alert cron, dead code paths)
    23→    23→
    24→    24→### القرار الاستراتيجي
    25→    25→
    26→    26→**لا يمكن نقل كود QuantDinger مباشرة إلى VIXOR** لأن الـ stack مختلف جذرياً (Python/Flask vs TypeScript/TanStack). لكن **يمكن است corósticoage:**
    27→    27→
    28→    28→1. **الـ patterns المعمارية** (Agent Gateway، capability tokens، SSE progress، idempotency) — تُعاد كتابتها بـ TypeScript
    29→    29→2. **الـ safe_exec sandbox** — يُعاد كتابته في Node.js `vm2` أو `isolated-vm` مع نفس الـ 3 طبقات
    30→    30→3. **الـ backtest engine logic** — يُعاد كتابتها بـ TypeScript مع نفس الـ candle-path simulation
    31→    31→4. **الـ strategy DSL** (`IndicatorStrategy` + `ScriptStrategy`) — يُعاد تصميمه لـ JavaScript/TypeScript
    32→    32→5. **الـ circuit breaker + rate limiter + cache** — يُعاد كتابتها بـ TypeScript (سهلة)
    33→    33→6. **الـ broker adapters** — تُعاد كتابتها لـ 4 exchanges أساسية (Binance, OKX, Bybit, Coinbase) — لا تحتاج ccxt
    34→    34→7. **الـ multi-provider LLM service** — يُعاد كتابته بـ TypeScript (7 providers)
    35→    35→8. **الـ multi-channel notifier** — يُعاد كتابته بـ TypeScript (Telegram + Email + Webhook)
    36→    36→9. **الـ credential encryption** — يُستبدل بـ `crypto.createCipheriv` في Node.js
    37→    37→10. **الـ experiment orchestration** — يُعاد كتابته بـ TypeScript

   213→   213→#### 1.1 نقل `safe_exec` sandbox إلى TypeScript (P0)
   214→   214→- **المصدر:** `audit/QuantDinger/backend_api_python/app/utils/safe_exec.py` (470 LOC)
   215→   215→- **الهدف:** `src/shared/safe-exec/index.ts` + `validator.ts` + `runner.ts`
   216→   216→- **الـ approach:**
   217→   217→  - **Layer 1 (regex blacklist):** نقل مباشر، نفس الـ patterns بالضبط
   218→   218→  - **Layer 2 (AST):** استخدام `@typescript-eslint/parser` أو `acorn` للـ AST walk، نفس الـ import whitelist (`numpy, pandas, math, json, datetime, time, collections, functools, itertools, statistics, decimal, fractions, operator, copy` — لكن بالـ JS equivalents)
   219→   219→  - **Layer 3 (restricted builtins):** استخدام `vm2` أو `isolated-vm` في Node.js
   220→   220→  - **Timeout:** `Promise.race` مع `setTimeout` + `worker_threads` للـ CPU-bound
   221→   221→  - **Subprocess isolation:** `worker_threads` (أخف من `child_process`)
   222→   222→- **الجهد:** 2-3 أيام
   223→   223→- **الاستخدام في VIXOR:** تنفيذ استراتيجيات Python/JS المقدمة من المستخدم بأمان

   238→   238→#### 1.3 نقل `credential_crypto` إلى Node.js `crypto` (P0)
   239→   239→- **المصدر:** `audit/QuantDinger/backend_api_python/app/utils/credential_crypto.py` (50 LOC)
   240→   240→- **الهدف:** `src/shared/crypto/credential-crypto.ts`
   241→   241→- **الـ approach:**
   242→   242→  ```typescript
   243→   243→  import { createCipheriv, createDecipheriv, scryptSync, randomBytes } from "crypto";
   244→   244→
   245→   245→  const KEY = scryptSync(process.env.SECRET_KEY!, "vixor-salt", 32); // AES-256
   246→   246→
   247→   247→  export function encryptCredential(data: object): string {
   248→   248→    const iv = randomBytes(16);
   249→   249→    const cipher = createCipheriv("aes-256-gcm", KEY, iv);
   250→   250→    const enc = Buffer.concat([cipher.update(JSON.stringify(data), "utf8"), cipher.final()]);
   251→   251→    const tag = cipher.getAuthTag();
   252→   252→    return Buffer.concat([iv, tag, enc]).toString("base64url");
   253→   253→  }
   254→   254→
   255→   255→  export function decryptCredential<T>(token: string): T {
   256→   256→    const buf = Buffer.from(token, "base64url");
   257→   257→    const iv = buf.subarray(0, 16);
   258→   258→    const tag = buf.subarray(16, 32);
   259→   259→    const enc = buf.subarray(32);
   260→   260→    const decipher = createDecipheriv("aes-256-gcm", KEY, iv);
   261→   261→    decipher.setAuthTag(tag);
   262→   262→    const dec = Buffer.concat([decipher.update(enc), decipher.final()]);
   263→   263→    return JSON.parse(dec.toString("utf8"));
   264→   264→  }
   265→   265→  ```

   882→   882→### Pattern 1: Capability-class scoped tokens
   883→   883→```
   884→   884→R = Read (markets, prices, klines, strategies, jobs)

   892→   892→### Pattern 2: SSE progress protocol
   893→   893→```
   894→   894→event: snapshot
   895→   895→data: {"job_id":"...","status":"running","progress":45}
   896→   896→
   897→   897→event: progress
   898→   898→data: {"seq":1,"ts":"...","data":{"phase":"backtesting","bar":45/200}}
   899→   899→
   900→   900→event: ping
   901→   901→(15s keepalive)
   902→   902→
   903→   903→event: result
   904→   904→data: {"status":"succeeded","result":{...}}
   905→   905→```
