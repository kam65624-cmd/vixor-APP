    10→## 1. Executive Summary
    11→
    12→QuantDinger is a **self-hosted, local-first AI quant operating system** that bundles,
    13→in a single Docker Compose stack, the full vertical slice of a retail/hobbyist
    14→algorithmic trading platform:
    15→
    16→* Flask 3.1 backend (gunicorn, single-process + gthread, Postgres + Redis)
    17→* Pre-built **Vue.js SPA** served by Nginx (Vue source lives in a private repo;
    18→  this open-source tree only ships `frontend/dist/`)
    19→* **Python strategy engine** with two authoring models:
    20→  * `IndicatorStrategy` (dataframe-based, signal-style) — the primary model
    21→  * `ScriptStrategy` (event-driven, `on_init(ctx)` + `on_bar(ctx, bar)` with
    22→    `ctx.buy/sell/close_position`) — for live execution
    23→* **Safe code execution** sandbox (`safe_exec.py`): regex + AST validation,
    24→  restricted `__builtins__`, whitelisted imports (numpy/pandas/math/json/etc.),
    25→  SIGALRM/ctypes-based timeout, optional multiprocessing subprocess isolation.
    26→* **Backtest engine** (`backtest.py`, ~5K lines) with multi-timeframe (1m/5m)
    27→  precision mode for crypto, long/short, leverage, commission/slippage,
    28→  trailing stops, equity curve, trade ledger, persisted to Postgres.
    29→* **Live trading** via direct REST clients (no ccxt for trade routing) for
    30→  Binance (spot+futures), OKX, Bitget, Bybit, Coinbase Exchange, Kraken
    31→  (spot+futures), KuCoin (spot+futures), Gate (spot+futures), Deepcoin, HTX,
    32→  plus IBKR (US stocks via TWS/IB Gateway) and MT5 (Forex, Windows-only).
    33→* **AI / Agent Gateway v1** (`/api/agent/v1`): capability-class scoped token
    34→  auth (R/W/B/N/C/T), async job runner with SSE progress streaming,
    35→  Idempotency-Key, audit log, paper-only trading by default, hard SaaS-mode
    36→  guard that rejects T-scope tokens at issuance.
    37→* **MCP server** (`mcp_server/`, also published to PyPI as `quantdinger-mcp`)
    38→  exposing a curated read + backtest subset of the Agent Gateway as MCP tools
    39→  for Cursor / Claude Code / Codex / OpenClaw / NanoBot. Supports stdio / sse
    40→  / streamable-http transports.
    41→* **Experiment orchestration** layer (`app/services/experiment/`): rule-based
    42→  market regime detection, structured (grid/random) parameter tuning, and
    43→  multi-round LLM-driven optimization with structured prompts.
    44→* **Reflection / self-calibration loop**: a background worker validates past
    45→  AI decisions against actual price outcomes, then re-calibrates BUY/SELL/HOLD
    46→  score thresholds per market.
    47→* **Notifications**: in-app + Email (SMTP) + Telegram (Bot API) + Twilio SMS
    48→  + Discord webhook + generic webhook + browser push.
    49→* **Multi-tenancy with billing**: credits, VIP plans, USDT-TRC20 on-chain
    50→  payment (HD-derived per-order address, TronGrid reconciliation), OAuth
    51→  (Google/GitHub), email verification, brute-force protection.
    52→* **Strategy community marketplace**: indicator publish/purchase/comments/
    53→  reviews with admin moderation.
    54→* **Polymarket prediction-market module**: cache + AI divergence analysis +
    55→  asset-level signal derivation.
    56→
    57→Total scale: **~25 backend route files, ~40 service files, ~1,117 lines of SQL
    58→schema (30+ tables), ~10 live-trading adapters, 10 data sources, 9 data
    59→providers, 11 tests files, 1 MCP server (11 tools)**. Frontend ships as ~30
    60→chunked JS bundles (~9MB+ minified) and supports 9 locales (zh-CN, zh-TW,
    61→en-US, ko-KR, ja-JP, fr-FR, de-DE, vi-VN, th-TH, ar-SA).

    96→### 2.2 Compose topology
    97→
    98→```
    99→Browser → (host Nginx 80/443) → frontend:80 (Nginx in container)
   100→                                  ├── serves dist/
   101→                                  └── /api/* → backend:5000 (gunicorn)
   102→                                                   ├── postgres:5432 (pool 5–50)
   103→                                                   └── redis:6379 (LRU 128MB)
   104→```
   105→
   106→* `BACKEND_URL` env var templated into `nginx.conf.template` via `entrypoint.sh`
   107→  (custom envsubst on a strict shell-format list so nginx's own `$host` etc.
   108→  stay literal).
   109→* `BACKEND_PORT`, `DB_PORT` default to `127.0.0.1:5000/5432` so only 80/443 are
   110→  public.
   111→* `IMAGE_PREFIX` allows swapping Docker Hub for China mirrors
   112→  (`docker.m.daocloud.io/library/`, `docker.xuanyuan.me/library/`).
   113→* `ALLOW_LOCAL_DESKTOP_BROKERS=true` (default) gates IBKR/MT5 routes — set to
   114→  `false` on SaaS cloud.
   115→
   116→### 2.3 Process / thread model
   117→
   118→* `create_app()` boots:
   119→  * `init_database()` (verifies Postgres connection)
   120→  * `ensure_admin_exists()` (creates admin user from `ADMIN_USER` / `ADMIN_PASSWORD`)
   121→  * `register_routes(app)` — 22 blueprints + the agent_v1 sub-package
   122→  * Background threads (all daemon, all in-process, no Celery / no RQ):
   123→    * `PendingOrderWorker` (polls `pending_orders` every 1s, batch 50)
   124→    * `PortfolioMonitor` (scheduled AI analysis on manual positions)
   125→    * `UsdtOrderWorker` (on-chain USDT payment reconciliation)
   126→    * `PolymarketWorker` (caches prediction-market data)
   127→    * `AICalibrationService.start_ai_calibration_worker` (offline threshold tuning)
   128→    * `ReflectionService.start_reflection_worker` (daily validation cycle)
   129→    * `restore_running_strategies()` (re-spawns `IndicatorStrategy` threads)
   130→* `TradingExecutor` is a singleton; each running strategy owns its own thread.
   131→* Gunicorn: 1 worker × 8 threads (default). All background work runs inside
   132→  that single worker process — multi-worker would duplicate background threads.
   133→
   134→### 2.4 Two-topology design
   135→
   136→A single binary serves both **self-hosted** (1 tenant, full feature set) and
   137→**SaaS/hosted** (N tenants, T-scope hard-blocked at issuance) modes. The
   138→selector is the env var `QUANTDINGER_DEPLOYMENT_MODE`
   139→(`saas`/`hosted`/`shared`/`multitenant`/`multi-tenant`). When in SaaS mode:
   140→
   141→* `POST /api/agent/v1/admin/tokens` rejects any payload containing scope `T`
   142→  with HTTP 403 (loud, not silent downgrade).
   143→* `paper_only` is force-pinned to `True` on every issued token.
   144→* `AGENT_LIVE_TRADING_ENABLED` is irrelevant because no token can have T.
   145→
   146→Tested by `tests/test_agent_v1_saas_guard.py` (13 cases).

   318→## 4. Strategy Engine Deep Dive
   319→
   320→This is the most valuable part of QuantDinger for VIXOR. The system supports
   321→**two distinct authoring models** that share storage but execute differently.
   322→
   323→### 4.1 Authoring model A — IndicatorStrategy (primary)
   324→
   325→* **Language**: pure Python (pandas + numpy).
   326→* **Convention**: user code receives `df` (OHLCV DataFrame) and must:
   327→  1. Compute boolean `df['buy']` and `df['sell']` columns (edge-triggered
   328→     recommended — `raw & ~raw.shift(1)`).
   329→  2. Build an `output` dict with `name`, `plots` (overlay/non-overlay series),
   330→     `signals` (buy/sell marks with text + color).
   331→  3. Optionally declare metadata via comments:
   332→     ```python
   333→     # @strategy stopLossPct 0.03
   334→     # @strategy takeProfitPct 0.06
   335→     # @strategy entryPct 1
   336→     # @strategy tradeDirection long
   337→     # @param rsi_len int 14 RSI period
   338→     ```
   339→* **`@strategy` keys** (parsed by `StrategyConfigParser`): `stopLossPct`,
   340→  `takeProfitPct`, `entryPct`, `trailingEnabled`, `trailingStopPct`,
   341→  `trailingActivationPct`, `tradeDirection` (long|short|both).
   342→* **`@param` keys** (parsed by `IndicatorParamsParser`): allow runtime
   343→  parameterization (int/float/bool/str) — surfaced in the IDE for sliders.
   344→* **Backtest path**: `BacktestService.run(indicator_code, market, symbol, ...)`
   345→  → `safe_exec_with_validation(code)` over an `exec_env` containing
   346→  `np`/`pd`/`df` → extract `df['buy']`/`df['sell']` → simulate bar-by-bar
   347→  with optional multi-timeframe precision (1m exec under 1D signal for
   348→  crypto, ≤15 days; 5m exec for ≤1 year).
   349→* **Live path**: `TradingExecutor.start_strategy(id)` spawns a daemon thread
   350→  that polls K-line every `decide_interval` seconds, re-runs the indicator
   351→  code, derives latest-bar signals, enqueues `pending_orders` rows.
   352→
   353→### 4.2 Authoring model B — ScriptStrategy (event-driven)
   354→
   355→* **Language**: pure Python (numpy + pandas).
   356→* **Convention**: user code defines `on_init(ctx)` (optional) and
   357→  `on_bar(ctx, bar)` (required). The `ctx` (`StrategyScriptContext`) exposes:
   358→  * `ctx.position` — `ScriptPosition` with `side`/`size`/`entry_price`/
   359→    `direction` (`+1`/`-1`/`0`), supports `bool()`/`int()`/`float()` and rich
   360→    comparison operators.
   361→  * `ctx.balance`, `ctx.equity`, `ctx.current_index`
   362→  * `ctx.bars(n=1)` — list of recent `ScriptBar`s (open/high/low/close/volume)
   363→  * `ctx.param(name, default)` — typed parameter access
   364→  * `ctx.log(msg)` — append to in-process log buffer
   365→  * `ctx.buy(price=None, amount=None)` / `ctx.sell(...)` / `ctx.close_position()`
   366→    — append to `_orders` queue, consumed by the runtime after each bar.
   367→* **Compile**: `compile_strategy_script_handlers(code)` runs
   368→  `safe_exec_with_validation` to extract the two callables.
   369→* **Live path**: `TradingExecutor` advances `ctx.current_index` bar-by-bar
   370→  in real time, calls `on_bar(ctx, bar)`, drains `_orders` into the
   371→  `pending_orders` queue with `signal_type` derived from the order action
   372→  and current position direction (e.g. `open_long` / `add_long` /
   373→  `close_long` / `open_short` / `add_short` / `close_short`).
   374→* **Backtest path**: `_run_script_strategy` in `BacktestService` mirrors this
   375→  flow for historical simulation.
   376→
   377→### 4.3 Safe execution sandbox (`app/utils/safe_exec.py`)
   378→
   379→Three layers of defense:
   380→
   381→1. **Static validation** (`validate_code_safety`):
   382→   * **Regex blacklist** for dangerous patterns: `os.system`, `subprocess`,
   383→     `__import__`, `eval(`/`exec(`/`compile(`/`open(`, `getattr(`/`setattr(`,
   384→     `__dict__`/`__class__`/`__subclasses__`/`__globals__`/`__code__`,
   385→     `globals(`/`vars(`/`dir(`/`breakpoint(`, plus `import os|sys|subprocess|
   386→     shutil|signal|resource|pymysql|sqlite3|psycopg2|sqlalchemy|requests|
   387→     urllib|http|socket|ftplib|telnetlib|smtplib|ssl|pickle|marshal|shelve|
   388→     ctypes|cffi|multiprocessing|threading|concurrent|asyncio|importlib|imp|
   389→     builtins|code|codeop|runpy|tempfile|glob|pathlib|io`.
   390→   * **AST walk** (fail-closed if parse fails): reject `ast.Import` /
   391→     `ast.ImportFrom` for any module root not in `SAFE_IMPORT_MODULES` =
   392→     `{numpy, pandas, math, json, datetime, time, collections, functools,
   393→     itertools, statistics, decimal, fractions, operator, copy}`. Reject
   394→     `ast.Call` to dangerous call names (`eval`/`exec`/`compile`/`__import__`/
   395→     `getattr`/`setattr`/`delattr`/`globals`/`vars`/`dir`/`breakpoint`/`open`/
   396→     `input`/`exit`/`quit`) and attribute access on dangerous modules. Reject
   397→     `ast.Attribute` for dangerous dunders.
   398→2. **Restricted `__builtins__`**: only a whitelisted set is available — types
   399→   (`bool`/`int`/`float`/`str`/`list`/`dict`/`set`/`tuple`/`frozenset`/...),
   400→   math (`abs`/`round`/`pow`/`min`/`max`/`sum`), iteration
   401→   (`len`/`enumerate`/`zip`/`map`/`filter`/`sorted`/`reversed`/`iter`/`next`/
   402→   `all`/`any`), strings (`repr`/`chr`/`ord`/`format`/`bin`/`hex`/`oct`),
   403→   type checks (`isinstance`/`issubclass`/`hasattr`/`callable`), `print`,
   404→   safe exceptions (`Exception`/`ValueError`/`TypeError`/...),
   405→   `staticmethod`/`classmethod`/`property`/`super`/`object`, constants
   406→   (`True`/`False`/`None`/`Ellipsis`/`NotImplemented`). `__import__` is
   407→   replaced with `_make_safe_import()` that only allows whitelisted roots.
   408→3. **Timeout + memory**:
   409→   * **Cross-platform timeout** via `timeout_context(seconds)`:
   410→     * Unix main thread: `signal.SIGALRM`
   411→     * Else (Windows or non-main thread): `threading.Timer` + ctypes
   412→       `PyThreadState_SetAsyncExc` to inject `TimeoutError` into the target
   413→       thread.
   414→   * Optional `RLIMIT_AS` memory cap on Linux when
   415→     `SAFE_EXEC_ENABLE_RLIMIT=true` (default false).
   416→4. **Subprocess isolation** (`safe_exec_isolated`): optional mode that runs
   417→   the user code in a `multiprocessing.Process` with its own memory space,
   418→   `RLIMIT_AS` enforced, pickle-serialized result pipe. Used for the
   419→   highest-isolation path (heavy indicator runs).
   420→
   421→### 4.4 Backtest engine internals
   422→
   423→* **Candle-path simulation**: for each bar, the engine infers a 4-point
   424→  price path — bullish bar = `open → low → high → close` (dip then rally),
   425→  bearish = `open → high → low → close` (rally then dip). This lets SL/TP
   426→  trigger intra-bar with realistic ordering.
   427→* **State machine**: `position ∈ {-size, 0, +size}` with `position_type ∈
   428→  {None, 'long', 'short'}`. Signals are queued, executed at next bar's open
   429→  price with slippage applied (long buys above open, short sells below).
   430→* **Risk features**: fixed SL/TP, trailing stop (activates after
   431→  `trailingActivationPct`, trails by `trailingStopPct`), liquidation
   432→  detection (capital < `min_capital_to_trade` → `is_liquidated=True`).
   433→* **Trade-direction modes**: `long` (long-only), `short` (short-only),
   434→  `both` (close-then-reverse on opposite signal).
   435→* **Multi-timeframe (MTF)**: when `enable_mtf=True` and market is crypto:
   436→  * ≤15 days → execute on 1m bars (max ~21,600 candles)
   437→  * 16–365 days → execute on 5m bars (max ~105,120 candles)
   438→  * >1 year → MTF disabled, fall back to native timeframe
   439→* **Persistence**: `qd_backtest_runs` (config snapshot, code_hash, result_json),
   440→  `qd_backtest_trades` (per-trade record), `qd_backtest_equity_points`
   441→  (equity curve samples). `run_type ∈ {indicator, strategy_indicator,
   442→  strategy_script}`.
   443→* **Storage schema auto-migration** on first use (`ensure_storage_schema()`)
   444→  — adds columns / creates tables if missing, so the system is resilient to
   445→  partial schema states.
   446→
   447→### 4.5 Live execution flow
   448→
   449→```
   450→TradingExecutor.start_strategy(id)
   451→  ├── load strategy row from qd_strategies_trading
   452→  ├── spawn daemon thread
   453→  └── loop:
   454→        ├── fetch latest K-line (cached 10s)
   455→        ├── fetch current price (KlineService)
   456→        ├── run indicator code via safe_exec
   457→        ├── extract latest-bar signals (df['buy'] / df['sell'])
   458→        ├── dedup via (strategy_id, symbol, signal_type, signal_ts) → skip if seen in 2× timeframe window
   459→        ├── enforce state machine: flat → open_long/open_short; long → add_long/reduce_long/close_long; short → add_short/reduce_short/close_short
   460→        ├── compute stake amount from entry_pct × equity × leverage
   461→        ├── INSERT into pending_orders (status='pending')
   462→        ├── SignalNotifier.notify_signal() — fire Telegram/Email/etc.
   463→        └── sleep decide_interval seconds
   464→
   465→PendingOrderWorker (separate thread):
   466→  ├── poll pending_orders WHERE status='pending' every 1s
   467→  ├── claim batch (row-level lock via SELECT FOR UPDATE)
   468→  ├── create_client(exchange_config, market_type) via factory
   469→  ├── place_order_from_signal()
   470→  ├── on success: apply_fill_to_local_position(), record_trade(), status='executed'
   471→  ├── on failure: attempts++, last_error; if attempts >= max_attempts → status='failed'
   472→  └── reclaim stuck orders older than 90s
   473→```

   488→### 4.7 AI strategy generation
   489→
   490→* `POST /api/indicator/aiGenerate` and `POST /api/strategies/ai-generate` —
   491→  ask the LLM (provider auto-detected) to produce indicator code from a
   492→  natural-language description, with a strongly-constrained prompt that
   493→  requires the output to follow the IndicatorStrategy convention
   494→  (`my_indicator_name`, `my_indicator_description`, `df['buy']`,
   495→  `df['sell']`, `output = {...}`).
   496→* `POST /api/experiment/ai-optimize` — multi-round LLM-driven optimization
   497→  that:
   498→  1. Detects current market regime via `MarketRegimeService`.
   499→  2. Builds a prompt with the indicator code, `@param` declarations, regime
   500→     summary, and previous-round results.
   501→  3. Asks LLM for N candidate parameter sets (5 by default), each with
   502→     `indicatorParams` + `riskParams` + `reasoning`.
   503→  4. Backtests each candidate, scores via `StrategyScoringService`.
   504→  5. Repeats up to `maxRounds` (default 3) or early-stops at score ≥ 82.
   505→  6. Returns ranked candidates + best output, ready to save as a strategy.

   509→## 5. Agent v1 System Deep Dive
   510→
   511→### 5.1 Identity model
   512→
   513→* **Token format**: `qd_agent_<urlsafe_32_bytes>` (prefix `qd_agent_`).
   514→* **Storage**: SHA-256 hash of full token stored in
   515→  `qd_agent_tokens.token_hash`. **Full token shown once at issuance** — never
   516→  retrievable later. Prefix (`qd_agent_xxxxxxxx`) shown in admin UI / audit
   517→  logs for traceability.
   518→* **Per-token attributes**:
   519→  * `scopes` — CSV subset of `{R, W, B, N, C, T}` (default `R`)
   520→  * `markets` — CSV allowlist or `*` (e.g. `Crypto,USStock`)
   521→  * `instruments` — CSV allowlist or `*` (e.g. `BTC/USDT,ETH/USDT`)
   522→  * `paper_only` — boolean (default `True`); T-scope tokens always start
   523→    paper-only
   524→  * `rate_limit_per_min` — sliding-window in-process limit (default 60)
   525→  * `status` — `active` / `revoked` / `expired`
   526→  * `expires_at` — nullable timestamp
   527→
   528→### 5.2 Auth pipeline (`agent_required(scope)` decorator)
   529→
   530→```
   531→1. _ensure_schema() — idempotent CREATE TABLE IF NOT EXISTS for qd_agent_tokens / _jobs / _audit / _paper_orders
   532→2. Extract Bearer token from Authorization header; reject 401 if missing/malformed
   533→3. Lookup token by SHA-256 hash → reject 401 if not found
   534→4. Verify status='active' → reject 401 if revoked
   535→5. Verify expires_at not past → reject 401 if expired
   536→6. Parse scopes; verify required scope is granted → reject 403 if missing
   537→7. Check rate limit (in-process sliding window) → reject 429 if exceeded
   538→8. Set g.agent_token + g.agent_user_id
   539→9. Execute handler
   540→10. _touch_token_last_used()
   541→11. _audit(scope_class, status_code, payload_summary, duration_ms) — INSERT into qd_agent_audit with redacted req/resp summaries
   542→```
   543→
   544→### 5.3 Idempotency
   545→
   546→`with_idempotency(kind)` context manager:
   547→
   548→* Reads `Idempotency-Key` header.
   549→* Queries `qd_agent_jobs` for `(agent_token_id, kind, idempotency_key)`.
   550→* If found → yields existing job → route returns `duplicate: true` with
   551→  original `job_id`.
   552→* If not found → yields None → caller performs work, persists new job row.
   553→* Enforced by a unique partial index on
   554→  `(agent_token_id, kind, idempotency_key) WHERE idempotency_key IS NOT NULL`.
   555→
   556→### 5.4 Async job runner (`agent_jobs.py`)
   557→
   558→* **Why not Celery?** Local-first deployments don't want a broker. A bounded
   559→  `ThreadPoolExecutor` keeps the operational surface small. The submit/poll
   560→  contract is unchanged if you later swap to Celery/RQ.
   561→* **`submit_job(user_id, agent_token_id, kind, request_payload, runner,
   562→  idempotency_key=None)`**:
   563→  * `INSERT INTO qd_agent_jobs (status='queued')` → returns `job_id` (uuid4 hex).
   564→  * Detects runner signature via `inspect.signature`:
   565→    * `runner(payload) -> result` — no streaming
   566→    * `runner(payload, on_progress) -> result` — streaming
   567→  * Dispatches `_run()` on the pool:
   568→    1. `status='running'`, `started_at=NOW()`
   569→    2. Synthetic `phase=running` progress event
   570→    3. Call runner; on success → `status='succeeded'`, `result=...`,
   571→       terminal progress event
   572→    4. On failure → `status='failed'`, `error=tb[-2000:]`, terminal event
   573→* **Progress streaming**:
   574→  * Per-job `deque(maxlen=200)` ring buffer keyed by `job_id`
   575→  * Monotonic `seq` per event
   576→  * Latest snapshot also persisted into `qd_agent_jobs.progress` JSONB so
   577→    cold reconnects can replay from DB
   578→  * `stream_progress(job_id, since_seq=0, idle_timeout_s=60)` generator
   579→    yields `{seq, ts, data, terminal}` records; cleans up state after
   580→    terminal
   581→* **SSE endpoint** (`GET /jobs/<job_id>/stream`):
   582→  * Frames: `snapshot` (current row) → `progress` (per event) → `ping` (~15s
   583→    keepalive) → `result` (terminal).
   584→  * Reconnect via `?since=<seq>` or standard `Last-Event-ID` header.
   585→  * If job already terminated at connect time → emit snapshot + result
   586→    immediately and close.
   587→
   588→### 5.5 Trading safety (class T)
   589→
   590→Three independent gates, all required for live execution:
   591→
   592→1. Token must have scope `T`.
   593→2. Token must have `paper_only=false` (operator flips explicitly).
   594→3. Server env `AGENT_LIVE_TRADING_ENABLED=true` (deployment kill switch).
   595→
   596→Until all three are met, `POST /api/agent/v1/quick-trade/orders` records a
   597→**paper order** into `qd_agent_paper_orders` using the latest K-line close as
   598→the simulated fill price — so AI workflows can exercise the full round-trip
   599→without touching exchange credentials.
   600→
   601→`POST /api/agent/v1/quick-trade/kill-switch` cancels all of the calling
   602→tenant's open paper orders in one call.
   603→
   604→### 5.6 Deployment-mode guard (`admin.py`)
   605→
   606→When `QUANTDINGER_DEPLOYMENT_MODE ∈ {saas, shared, hosted, multitenant,
   607→multi-tenant}`:
   608→
   609→* `POST /admin/tokens` rejects any payload with `T` in scopes → HTTP 403
   610→  with explicit message (no silent downgrade).
   611→* `paper_only` force-pinned to `True` regardless of payload.
   612→* Both guards run at issuance time, so a SaaS instance never has an at-rest
   613→  token capable of routing real-money trades — even with
   614→  `AGENT_LIVE_TRADING_ENABLED=true` misconfigured.
   615→
   616→### 5.7 Audit log
   617→
   618→`qd_agent_audit` columns: `user_id`, `agent_token_id`, `agent_name`, `route`,
   619→`method`, `scope_class`, `status_code`, `idempotency_key`,
   620→`request_summary` (redacted JSONB, ≤8KB), `response_summary` (redacted
   621→JSONB), `duration_ms`, `created_at`.
   622→
   623→* Redaction: `password`, `secret`, `token`, `apikey`, `api_key`,
   624→  `authorization` keys are recursively replaced with `<redacted>`. Long
   625→  strings (>500 chars) truncated. Lists truncated to 20 items.
   626→* Indexed on `(user_id, created_at DESC)`, `(agent_token_id, created_at
   627→  DESC)`, `(scope_class)`.

   719→### 7.2 Resilience layer
   720→
   721→* **CircuitBreaker** (`circuit_breaker.py`): CLOSED/OPEN/HALF_OPEN state
   722→  machine. Per-source failure tracking with cooldown. Default thresholds:
   723→  realtime (2 failures → 3min cooldown), akshare (3 failures → 5min
   724→  cooldown). When OPEN, requests short-circuit to the next fallback source.
   725→* **RateLimiter** (`rate_limiter.py`): per-source min-interval + jitter.
   726→  Pre-instantiated limiters for eastmoney (2s+1-3s jitter), tencent (1s+0.5-1.5s
   727→  jitter), akshare (2s+1.5-3.5s jitter). Plus a `retry_with_backoff`
   728→  decorator with exponential backoff (`base × exp^(attempt-1)`, capped at
   729→  `max_delay`, ±20% jitter).
   730→* **Random User-Agent rotation** (12 desktop UAs: Chrome/Firefox/Safari/Edge
   731→  on Windows/Mac/Linux).
   732→* **DataCache** (`cache_manager.py`): thread-safe `OrderedDict` LRU with
   733→  per-key TTL. Default `max_size=1000`, `default_ttl=600s`.
   734→* **KlineService**: K-line fetch with Redis cache (or in-memory fallback),
   735→  per-timeframe TTL (1m→5s, 3m→30s, 5m→60s, 15m→300s, ..., 1D→300s).
   736→* **Proxy bypass for CN financial sources**: `run.py` injects `NO_PROXY`
   737→  for `.eastmoney.com`, `.sina.com.cn`, `.10jqka.com.cn`, `.ssec.com.cn`,
   738→  `.szse.cn`, `.hexun.com`, `.cninfo.com.cn`, `.gtimg.cn`, `.qq.com`,
   739→  `.tencent.com`, `.mairui.club`, `.akshare.xyz`, `.baostock.com`, etc.,
   740→  so domestic CN data sources bypass overseas proxies.

   879→### 9.8 Notable schema patterns
   880→
   881→* **All tables use `SERIAL` or `BIGSERIAL` PRIMARY KEY** (no UUIDs in DB).
   882→* **Foreign keys** use `ON DELETE CASCADE` for ownership chains (user →
   883→  strategies → positions/trades).
   884→* **Soft migrations via `DO $$ ... END $$` blocks** that check
   885→  `information_schema.columns` before `ALTER TABLE ADD COLUMN` — so the same
   886→  `init.sql` is idempotent across upgrades.
   887→* **No row-level security (RLS)** — tenant isolation enforced at the
   888→  application layer via `user_id` filters in every query.
   889→* **No stored procedures, triggers, or views** — all logic in Python.
   890→* **JSONB** used liberally for flexible payloads
   891→  (`exchange_config`, `trading_config`, `indicator_config`,
   892→  `notification_config`, `request`, `result`, `progress`,
   893→  `request_summary`, `response_summary`, `reasons`, `scores`,
   894→  `indicators_snapshot`, `raw_result`, `outcome_tokens`, `key_factors`,
   895→  `entry_suggestion`, `chart_templates`, `notification_settings`).

   914→
   915→1. If `LLM_PROVIDER` env (or `llm.provider` config) set → use that
   916→   explicitly.
   917→2. Otherwise auto-detect by API key presence, priority order:
   918→   `DeepSeek > Grok > MiniMax > OpenAI > Google > OpenRouter`.
   919→3. If none configured → default to OpenRouter (will fail on first call with
   920→   a clear error message).

   923→
   924→* **OpenAI-compatible** (OpenAI, DeepSeek, Grok, OpenRouter, MiniMax, Custom):
   925→  standard `/chat/completions` POST with optional
   926→  `response_format={"type": "json_object"}` for JSON mode.
   927→* **Google Gemini**: bespoke `_call_google_gemini()` that converts OpenAI
   928→  message format to Gemini `contents`/`parts` format, with
   929→  `systemInstruction` for system messages and `responseMimeType:
   930→  "application/json"` for JSON mode.
   931→
   932→### 10.4 Error handling
   933→
   934→* Non-2xx responses produce detailed error messages with provider-specific
   935→  hints (e.g. OpenRouter 403 → "可能原因：API 密钥无效/过期、余额不足、或无
   936→  模型权限"; 404 → "可能原因：模型不可用或账户隐私/数据策略限制").
   937→* Empty content → `ValueError("Model X returned empty content")`.
   938→* Missing `choices` → `ValueError("API response is missing 'choices'")`.
   939→
   940→### 10.5 Model normalization
   941→
   942→`_normalize_model_for_provider(model, provider)`:
   943→
   944→* If provider is OpenRouter → keep `vendor/model` format.
   945→* Otherwise → strip prefix (`openai/gpt-4o` → `gpt-4o`).
   946→* If prefix doesn't match the active provider → fall back to provider's
   947→  default model (prevents sending `gpt-4o` to DeepSeek).

   964→### 10.7 Self-calibration loop
   965→
   966→```
   967→qd_analysis_memory (validated rows)
   968→        │
   969→        ▼
   970→ReflectionService.run_verification_cycle()  (daily, background thread)
   971→        │ 1. Validate unvalidated rows older than 7 days
   972→        │    - Fetch current price for (market, symbol)
   973→        │    - Compute actual_return_pct = (current - price_at_analysis) / price_at_analysis × 100
   974→        │    - Set was_correct based on decision:
   975→        │       BUY correct if return > +2%
   976→        │       SELL correct if return < -2%
   977→        │       HOLD correct if |return| <= 5%
   978→        │    - Set validated_at = NOW()
   979→        ▼
   980→AICalibrationService.calibrate_market(market)
   981→        │ 2. For each candidate abs_threshold in [10,12,14,16,18,20,22,25,30]:
   982→        │    - For each validated row, predict decision from consensus_score:
   983→        │        score >= +thr → BUY
   984→        │        score <= -thr → SELL
   985→        │        else → HOLD
   986→        │    - Compute accuracy = correct_predictions / total_predictions
   987→        │ 3. Pick threshold with best accuracy (min 80 samples)
   988→        │ 4. INSERT into qd_ai_calibration (market, buy_threshold, sell_threshold, ...)
   989→        ▼
   990→FastAnalysisService reads qd_ai_calibration on next call
   991→        → uses tuned thresholds for BUY/SELL/HOLD decisions
   992→```

  1061→## 12. Auth & Security
  1062→
  1063→### 12.1 Auth pipelines (two parallel, never crossable)
  1064→
  1065→| Pipeline | Used by | Token format | Storage | Decorator |
  1066→|----------|---------|--------------|---------|-----------|
  1067→| Human JWT | Browser SPA, OAuth callbacks | `jwt.encode(payload, SECRET_KEY, HS256)`, 7-day expiry | Not stored server-side; `token_version` in DB enforces single-client | `@login_required`, `@admin_required` |
  1068→| Agent token | External AI agents, MCP server | `qd_agent_<urlsafe_32_bytes>` | SHA-256 hash in `qd_agent_tokens.token_hash` | `@agent_required(scope)` |
  1069→
  1070→A JWT is **never** accepted on `/api/agent/v1/*` and an agent token is
  1071→**never** accepted on `/api/*`. No accidental cross-use.
  1072→
  1073→### 12.2 JWT specifics
  1074→
  1075→* Algorithm: HS256.
  1076→* Payload: `exp` (7 days), `iat`, `sub` (username), `user_id`, `role`,
  1077→  `token_version`.
  1078→* **Single-client enforcement**: every login increments `qd_users.token_version`;
  1079→  JWT verification checks DB `token_version` matches the one in the token —
  1080→  mismatch → reject (kicks older sessions).
  1081→* Auto-regenerated `SECRET_KEY` if running in production with the default
  1082→  example value (defensive; `run.py` main()).
  1083→
  1084→### 12.3 OAuth2
  1085→
  1086→* Providers: Google, GitHub.
  1087→* CSRF state stored in `qd_oauth_states` (cross-worker safe — not in-memory).
  1088→* State TTL: 20 min (env: `OAUTH_STATE_TTL_MINUTES`).
  1089→* Auto-creates user on first OAuth login; links to existing user if email
  1090→  matches.
  1091→* Frontend redirect: PC hash mode (`/#/user/login`) or mobile history mode
  1092→  (preserves full path) — auto-detected by URL shape.
  1093→
  1094→### 12.4 Email verification & brute-force protection
  1095→
  1096→* 6-digit numeric code, 10-min expiry, max-5 attempts / 30-min lockout per
  1097→  email.
  1098→* `qd_login_attempts` tracks per-IP and per-account attempts.
  1099→* `qd_verification_codes.attempts` and `last_attempt_at` enforce code
  1100→  attempt limits.
  1101→
  1102→### 12.5 Credential encryption
  1103→
  1104→* `cryptography.fernet.Fernet` with key =
  1105→  `urlsafe_b64encode(hashlib.sha256(SECRET_KEY.encode()).digest())`.
  1106→* `encrypt_credential_blob(plaintext_json)` → Fernet-encrypted string for
  1107→  DB storage in `qd_exchange_credentials.encrypted_config`.
  1108→* `decrypt_credential_blob(stored)` → plaintext JSON; raises `ValueError`
  1109→  on wrong key (so rotating `SECRET_KEY` invalidates all stored credentials
  1110→  — must re-enter exchange API keys).
  1111→* API key hint (`api_key_hint` column) stores first 4 + last 4 chars for
  1112→  UI display.
  1113→* Secrets are masked in logs via `mask_secret()` (e.g.
  1114→  `ABCD...wxyz`).
  1115→
  1116→### 12.6 Rate limiting
  1117→
  1118→* **Per-token agent rate limit**: in-process sliding window,
  1119→  `rate_limit_per_min` per token (default 60). Returns HTTP 429 with
  1120→  `retriable: true` when exceeded.
  1121→* **Per-IP / per-account login throttling**: `qd_login_attempts` table.
  1122→* **Per-data-source rate limiters**: `RateLimiter` instances for
  1123→  eastmoney/tencent/akshare (min-interval + jitter).
  1124→* **Circuit breaker**: per-source failure tracking with cooldown (3min
  1125→  realtime, 5min akshare).
  1126→* **External API rate limits**: Finnhub (60/min), CCXT (built-in
  1127→  `enableRateLimit: true`).
  1128→
  1129→### 12.7 Code execution sandbox
  1130→
  1131→See §4.3 for the full safe_exec analysis. Key points:
  1132→
  1133→* Three-layer defense: regex blacklist → AST walk → restricted `__builtins__`.
  1134→* Whitelisted imports only: `numpy`, `pandas`, `math`, `json`, `datetime`,
  1135→  `time`, `collections`, `functools`, `itertools`, `statistics`, `decimal`,
  1136→  `fractions`, `operator`, `copy`.
  1137→* Cross-platform timeout (SIGALRM on Unix main thread, ctypes
  1138→  `PyThreadState_SetAsyncExc` elsewhere).
  1139→* Optional subprocess isolation via `multiprocessing.Process` with
  1140→  `RLIMIT_AS`.
  1141→* Fail-closed: AST parse failure → reject.
  1142→
  1143→### 12.8 Other security features
  1144→
  1145→* **SafeJSONProvider** in `app/__init__.py`: sanitizes NaN/Infinity to
  1146→  `null` in all JSON responses (RFC 8259 compliance).
  1147→* **CORS**: enabled globally via flask-cors (consider tightening for
  1148→  production).
  1149→* **Security headers**: `X-Frame-Options: SAMEORIGIN`,
  1150→  `X-Content-Type-Options: nosniff`, `X-XSS-Protection: 1; mode=block` in
  1151→  nginx.
  1152→* **Audit logs**: `qd_security_logs` (human auth events) +
  1153→  `qd_agent_audit` (every agent call).
  1154→* **Egress IP detection** for Binance IP whitelist debugging
  1155→  (`https://ifconfig.me/ip`).

  1240→transport resolution (stdio default, alias mapping, unknown exits), HTTP
  1241→settings shim tolerates FastMCP version drift.
  1242→

  1246→  backtest → live-trade flow.
  1247→* **No load / performance tests**.
  1248→* **No tests for the strategy runtime itself** (`trading_executor.py`,
  1249→  `backtest.py`) — these are the most complex modules.

  1257→## 15. Notable Patterns Worth Reusing
  1258→
  1259→### 15.1 Capability-class scoped agent tokens
  1260→
  1261→The R/W/B/N/C/T taxonomy with per-token market/instrument allowlists +
  1262→`paper_only` flag is a clean, auditable model for giving AI agents
  1263→least-privilege access to a trading platform. The dual-gate design (token
  1264→`paper_only=false` AND server `AGENT_LIVE_TRADING_ENABLED=true`) is a
  1265→solid defense-in-depth pattern. The SaaS-mode issuance-time guard
  1266→(rejecting T-scope outright rather than silently downgrading) is
  1267→particularly well thought out.
  1268→
  1269→### 15.2 Idempotency-Key with unique partial index
  1270→
  1271→The Postgres pattern:
  1272→```sql
  1273→CREATE UNIQUE INDEX idx_agent_jobs_idem
  1274→    ON qd_agent_jobs(agent_token_id, kind, idempotency_key)
  1275→    WHERE idempotency_key IS NOT NULL;
  1276→```
  1277→…is an elegant way to enforce idempotency at the DB layer without bloating
  1278→the index with NULL idempotency keys.
  1279→
  1280→### 15.3 SSE progress streaming with resume
  1281→
  1282→The `snapshot → progress → ping → result` SSE frame protocol with
  1283→`?since=<seq>` (or `Last-Event-ID`) resume is a clean pattern for
  1284→long-running jobs. The per-job `deque(maxlen=200)` ring buffer +
  1285→latest-snapshot-in-DB hybrid gives both low-latency live streaming and
  1286→cold-reconnect replay.
  1287→
  1288→### 15.4 Three-layer safe code execution
  1289→
  1290→Regex blacklist → AST walk → restricted `__builtins__` with whitelisted
  1291→imports, plus cross-platform timeout (SIGALRM + ctypes fallback) and
  1292→optional subprocess isolation. The fail-closed approach (AST parse failure
  1293→→ reject) is the right default.
  1294→
  1295→### 15.5 Multi-tier data source fallback with circuit breaker
  1296→
  1297→`CircuitBreaker` (CLOSED/OPEN/HALF_OPEN) + per-source `RateLimiter` +
  1298→`retry_with_backoff` decorator + `DataCache` LRU is a robust pattern for
  1299→surviving flaky public financial APIs (eastmoney/sina/akshare/tencent).
  1300→
  1301→### 15.6 Self-calibration feedback loop
  1302→
  1303→The `qd_analysis_memory → reflection → ai_calibration → fast_analysis`
  1304→loop (validate past decisions → recompute thresholds → feed back into
  1305→next analysis) is a practical, low-cost approach to making AI trading
  1306→decisions self-tuning without requiring model retraining.
  1307→
  1308→### 15.7 Single-binary dual-topology deployment
  1309→
  1310→Same codebase serves self-hosted (1 tenant, full features) and SaaS
  1311→(N tenants, T-scope hard-blocked) via a single env var. The guard runs at
  1312→issuance time so existing tokens survive a mode switch (no destructive
  1313→migration), but new issuances immediately follow the new rules.
  1314→
  1315→### 15.8 JSON sanitization at the framework layer
  1316→
  1317→`SafeJSONProvider` that recursively replaces NaN/Infinity with `null`
  1318→before serialization is a one-line fix that prevents every frontend
  1319→consumer from breaking on `JSON.parse()` of invalid JSON tokens. Worth
  1320→adopting in any Flask project that returns float-heavy responses.
  1321→
  1322→### 15.9 Cross-worker OAuth state via DB
  1323→
  1324→Storing OAuth CSRF state in `qd_oauth_states` (not in-memory) is the only
  1325→correct way to do OAuth in a multi-worker / multi-replica deployment.
  1326→The pattern generalizes to any stateful callback flow.
  1327→
  1328→### 15.10 Candle-path simulation for backtests
  1329→
  1330→The 4-point intra-bar path inference (bullish = open→low→high→close,
  1331→bearish = open→high→low→close) is a simple but effective heuristic for
  1332→realistic SL/TP triggering within a single bar — better than assuming
  1333→worst-case or best-case fills.
  1334→

  1337→## 16. Gaps / Limitations
  1338→
  1339→### 16.1 No real-money agent trading implemented
  1340→
  1341→`agent_v1/quick_trade.py` returns HTTP 501 ("Live agent trading is not
  1342→implemented in this build") even when both `paper_only=false` and
  1343→`AGENT_LIVE_TRADING_ENABLED=true`. The full T-scope live execution path
  1344→is tracked under roadmap A6 and **not yet shipped**. The trading surface
  1345→exists only via the human Quick Trade flow and the `TradingExecutor` +
  1346→`PendingOrderWorker` for human-created strategies.
  1347→
  1348→### 16.2 Single-process background workers
  1349→
  1350→All background workers (portfolio monitor, pending order worker, USDT
  1351→order worker, polymarket worker, AI calibration, reflection, strategy
  1352→restore) run as daemon threads inside the single gunicorn worker. This:
  1353→
  1354→* Limits horizontal scaling (can't run multiple backend replicas without
  1355→  duplicating workers).
  1356→* Means a worker crash takes down the whole backend.
  1357→* No job queue / broker (Celery, RQ, Dramatiq) — operator must add one
  1358→  to scale.
  1359→
  1360→### 16.3 Frontend source not in this repo
  1361→
  1362→The Vue source is in a private repo. Open-source contributors can only
  1363→modify pre-built `dist/` (which is minified and chunk-hashed). Frontend
  1364→changes require access to the private repo. This is a deliberate choice
  1365→(see `CONTRIBUTING.md`) but limits community contribution to backend.
  1366→
  1367→### 16.4 Test coverage gaps
  1368→
  1369→* No tests for `safe_exec.py` (the security boundary).
  1370→* No tests for `backtest.py` (5K LOC, the core engine).
  1371→* No tests for `trading_executor.py` (3.8K LOC, the live engine).
  1372→* No tests for `strategy_compiler.py` (codegen).
  1373→* No tests for any of the live_trading exchange clients.
  1374→* No end-to-end / integration tests.
  1375→* No load / performance tests.
  1376→
  1377→### 16.5 No walk-forward / OOS validation
  1378→
  1379→Per `docs/AI_TRADING_SYSTEM_PLAN_CN.md`, walk-forward and out-of-sample
  1380→scoring are deferred to "Phase 3" and not yet implemented. The experiment
  1381→scoring (`StrategyScoringService`) only evaluates on the same backtest
  1382→window — overfitting risk is real.
  1383→
  1384→### 16.6 No paper-trading champion promotion path
  1385→
  1386→"Phase 4" (paper trading → champion strategy promotion) is also deferred.
  1387→The Agent Gateway's T-scope paper-order ledger is the closest thing, but
  1388→there's no automated champion-selection flow yet.
  1389→
  1390→### 16.7 In-process rate limiting (not distributed)
  1391→
  1392→The agent-token rate limiter uses an in-process `dict[int, list[float]]`
  1393→sliding window. This works for single-instance deployments but breaks
  1394→down with multiple backend replicas (each replica has its own counter).
  1395→For SaaS multi-replica, you'd need Redis-based rate limiting.
  1396→
  1397→### 16.8 No structured logging
  1398→
  1399→Logging uses Python's stdlib `logging` with rotating file + console
  1400→handlers. No structured JSON logging, no trace IDs, no OpenTelemetry
  1401→integration. Hard to correlate requests across services in production.
  1402→
  1403→### 16.9 Heavy reliance on `psycopg2.RealDictCursor`
  1404→
  1405→Every query returns `dict`-style rows. This is convenient but slower than
  1406→typed tuples. For hot paths (e.g., `PendingOrderWorker` polling
  1407→`pending_orders` every second), this could become a bottleneck.
  1408→
  1409→### 16.10 Schema migrations are manual `DO $$ ... END $$` blocks
  1410→
  1411→No Alembic, no migration framework. Schema changes require editing
  1412→`init.sql` and adding `IF NOT EXISTS` checks. Forward-only; no
  1413→down-migrations. Acceptable for a self-hosted project but doesn't scale
  1414→to a SaaS with frequent schema changes.
  1415→
  1416→### 16.11 No retry / DLQ for failed orders
  1417→
  1418→`pending_orders` has `max_attempts` (default 10) but no dead-letter
  1419→queue. Failed orders just sit with `status='failed'` and `last_error`
  1420→text. No automated retry policy beyond the worker's 10-attempt loop.
  1421→
  1422→### 16.12 Legacy SQLite references
  1423→
  1424→Some code paths still use `?` placeholders (SQLite-style), which
  1425→`db_postgres.py` auto-converts to `%s`. This is a smell — indicates the
  1426→codebase was migrated from SQLite and not fully cleaned up.
  1427→
  1428→### 16.13 No multi-currency PnL
  1429→
  1430→All PnL is computed in the quote currency of the symbol (typically USDT
  1431→for crypto, USD for stocks). No FX conversion layer for cross-currency
  1432→portfolio aggregation.
  1433→
  1434→### 16.14 Limited asset class coverage for live trading
  1435→
  1436→Live trading supports crypto (10 exchanges), US stocks (IBKR), and Forex
  1437→(MT5). No live trading for CN stocks, HK stocks, MOEX, or futures —
  1438→those markets are data-only.
  1439→

  1442→## 17. Reuse Candidates for VIXOR (Top 10)
  1443→
  1444→Ranked by (value to VIXOR ÷ effort to port). All are Apache-2.0 licensed
  1445→(code), so reuse is permitted as long as QuantDinger branding is removed
  1446→for derivative distributions (per TRADEMARKS.md §5).
  1447→
  1448→### 17.1 ★ Safe code execution sandbox (`app/utils/safe_exec.py`)
  1449→
  1450→* **Why**: 470 LOC, self-contained, no internal dependencies beyond
  1451→  `app.utils.logger`. Three-layer defense (regex + AST + restricted
  1452→  builtins) with cross-platform timeout and optional subprocess isolation.
  1453→  Battle-tested against user-submitted Python strategy code.
  1454→* **Effort**: Low — copy `safe_exec.py`, swap the logger import, write
  1455→  tests for the security boundary (which QuantDinger lacks).
  1456→* **VIXOR use**: Execute user-submitted strategy / indicator code with
  1457→  strong isolation. Critical for any platform that lets users write
  1458→  Python strategies.
  1459→
  1460→### 17.2 ★ Agent Gateway auth + jobs + audit pattern (`app/utils/agent_auth.py` + `app/utils/agent_jobs.py` + `app/routes/agent_v1/`)
  1461→
  1462→* **Why**: Clean, well-documented implementation of capability-class
  1463→  scoped tokens (R/W/B/N/C/T), per-token rate limiting, Idempotency-Key
  1464→  with DB unique partial index, async job runner with SSE progress
  1465→  streaming, redacted audit logging. The SaaS-mode issuance-time guard is
  1466→  particularly well-designed.
  1467→* **Effort**: Medium — needs adaptation to VIXOR's auth/DB layer, but the
  1468→  core pattern (token hash at rest, scope enum, in-process rate limiter,
  1469→  job table with progress JSONB) is portable.
  1470→* **VIXOR use**: Give external AI agents (Cursor, Claude Code, custom
  1471→  automations) scoped, auditable access to VIXOR's research/backtest/
  1472→  trading surface.
  1473→
  1474→### 17.3 ★ Backtest engine (`app/services/backtest.py` — core ~2000 LOC of the 4974)
  1475→
  1476→* **Why**: Mature backtest engine with multi-timeframe precision (1m/5m
  1477→  for crypto), long/short/both trade directions, leverage, commission/
  1478→  slippage, fixed + trailing SL/TP, liquidation detection, candle-path
  1479→  simulation, equity-curve + trade-ledger persistence. Engine version
  1480→  stamped (`strategy-backtest-v1`).
  1481→* **Effort**: High — 5K LOC, tightly coupled to QuantDinger's data
  1482→  sources and DB schema. Better to extract the simulation core
  1483→  (`_simulate_signals_with_mtf`, `_infer_candle_path`, trade state
  1484→  machine) and re-wrap with VIXOR's data layer.
  1485→* **VIXOR use**: Drop-in backtest engine for any indicator-driven
  1486→  strategy. The `run_strategy_snapshot()` entrypoint is already
  1487→  snapshot-based and framework-agnostic.
  1488→
  1489→### 17.4 ★ Strategy runtime + IndicatorStrategy DSL (`app/services/strategy_script_runtime.py` + `app/services/indicator_params.py`)
  1490→
  1491→* **Why**: The `IndicatorStrategy` DSL (Python + `df['buy']`/`df['sell']`
  1492→  + `output = {...}` + `@strategy`/`@param` annotations) is a clean,
  1493→  low-friction authoring model. The `ScriptStrategy` event-driven model
  1494→  (`on_init`/`on_bar` + `ctx.buy/sell/close_position`) is a clean
  1495→  escape hatch for stateful strategies. Both share storage and use the
  1496→  same safe_exec sandbox.
  1497→* **Effort**: Medium — needs the safe_exec sandbox (§17.1) and a backtest
  1498→  engine (§17.3) to be useful. The DSL itself is ~600 LOC across the two
  1499→  files.
  1500→* **VIXOR use**: Let users write strategies in Python without learning a
  1501→  proprietary DSL. The `@param` annotation system gives the IDE
  1502→  auto-generated parameter sliders for free.
  1503→
  1504→### 17.5 ★ Experiment orchestration (`app/services/experiment/`)
  1505→
  1506→* **Why**: 5 files, ~700 LOC total. Rule-based regime detection (5
  1507→  regimes, 6 features), structured grid/random parameter tuning, LLM-
  1508→  driven multi-round optimization with early-stop. Clean separation of
  1509→  concerns (regime / evolution / scoring / runner / prompts).
  1510→* **Effort**: Medium — depends on a backtest engine (§17.3) and LLM
  1511→  service (§17.7). The regime detector and scoring service are
  1512→  standalone.
  1513→* **VIXOR use**: Automate the "AI researches → backtests → scores →
  1514→  proposes best strategy" loop. The scoring service's multi-factor
  1515→  weighted score (return / sharpe / drawdown / stability / win_rate /
  1516→  profit_factor) with letter grades is a reusable primitive.
  1517→
  1518→### 17.6 ★ Live trading adapter pattern (`app/services/live_trading/`)
  1519→
  1520→* **Why**: 11 crypto exchanges + IBKR + MT5, all behind a uniform
  1521→  `BaseRestClient` interface with `ping/get_account/place_order/
  1522→  cancel_order/get_positions/get_fee_rate`. Factory pattern with
  1523→  demo/testnet awareness. Per-exchange symbol normalization.
  1524→  `LiveOrderResult` dataclass standardizes results.
  1525→* **Effort**: High — each exchange client is 200–800 LOC of REST signing
  1526→  logic. Pick the exchanges VIXOR needs (probably Binance, OKX, Bybit,
  1527→  Coinbase to start) and port those.
  1528→* **VIXOR use**: Skip building exchange integrations from scratch. The
  1529→  direct-REST approach (no ccxt for orders) gives finer control over
  1530→  signing, hedging, broker codes, and demo/testnet routing than ccxt
  1531→  allows.
  1532→
  1533→### 17.7 ★ Multi-provider LLM service (`app/services/llm.py`)
  1534→
  1535→* **Why**: 629 LOC, 7 providers (OpenRouter, OpenAI, Gemini, DeepSeek,
  1536→  Grok, MiniMax, Custom OpenAI-compatible). Auto-detect by API key.
  1537→  Provider-specific error messages. Model name normalization (strips
  1538→  `vendor/` prefix when calling direct providers). Fallback model
  1539→  support.
  1540→* **Effort**: Low — copy `llm.py`, swap the config imports. Depends on
  1541→  `requests` only.
  1542→* **VIXOR use**: Avoid vendor lock-in to a single LLM provider. Let
  1543→  users bring their own key. The auto-detect-by-key pattern means zero
  1544→  config for users who already have an OpenAI/DeepSeek/Gemini key.
  1545→
  1546→### 17.8 ★ Multi-channel signal notifier (`app/services/signal_notifier.py`)
  1547→
  1548→* **Why**: 912 LOC, 6 channels (browser, email, Telegram, SMS via Twilio,
  1549→  Discord webhook, generic HMAC-signed webhook). User-timezone-aware
  1550→  timestamps. Per-strategy `notification_config` JSON schema. HTML-
  1551→  formatted messages.
  1552→* **Effort**: Low-Medium — copy `signal_notifier.py`, swap DB imports.
  1553→  Each channel is ~100 LOC and independent.
  1554→* **VIXOR use**: Out-of-the-box multi-channel notifications for strategy
  1555→  signals, portfolio alerts, AI analysis triggers.
  1556→
  1557→### 17.9 ★ Data source resilience layer (`app/data_sources/circuit_breaker.py` + `rate_limiter.py` + `cache_manager.py`)
  1558→
  1559→* **Why**: ~600 LOC total. `CircuitBreaker` (CLOSED/OPEN/HALF_OPEN state
  1560→  machine), `RateLimiter` (min-interval + jitter), `retry_with_backoff`
  1561→  decorator (exponential + jitter), `DataCache` (thread-safe LRU + TTL).
  1562→  Pre-instantiated limiters for common CN financial APIs.
  1563→* **Effort**: Low — copy the three files. No internal dependencies.
  1564→* **VIXOR use**: Survive flaky public financial APIs. The circuit
  1565→  breaker pattern is essential for any platform that aggregates from
  1566→  multiple data sources.
  1567→
  1568→### 17.10 ★ Credential encryption (`app/utils/credential_crypto.py`)
  1569→
  1570→* **Why**: 50 LOC, self-contained. Fernet encryption with key derived
  1571→  from `SECRET_KEY` via `SHA-256 → urlsafe-b64`. Encrypt/decrypt
  1572→  functions for JSON blobs. Wrong-key raises `ValueError` (fail-closed).
  1573→* **Effort**: Trivial — copy the file, set `SECRET_KEY`.
  1574→* **VIXOR use**: Encrypt exchange API keys / broker credentials at rest.
  1575→  The pattern (derive Fernet key from a single server secret) is simple,
  1576→  auditable, and well-understood.
