    71→## Try in 2 minutes
    72→
    73→**Prerequisites:** [Docker](https://docs.docker.com/get-docker/) with Compose (Docker Desktop on Windows/macOS, or Docker Engine + Compose plugin on Linux), and **Git**. Node.js is **not** required (prebuilt UI is in `frontend/dist`).
    74→
    75→### macOS / Linux (Bash)
    76→
    77→One line (or run the same steps separately):
    78→
    79→```bash
    80→git clone https://github.com/brokermr810/QuantDinger.git && cd QuantDinger && cp backend_api_python/env.example backend_api_python/.env && chmod +x scripts/generate-secret-key.sh && ./scripts/generate-secret-key.sh && docker-compose up -d --build
    81→```
    82→
    83→If `./scripts/generate-secret-key.sh` fails with “Permission denied”, run `chmod +x scripts/generate-secret-key.sh` and retry. If `docker-compose` is not found, try `docker compose` (Compose V2).
    84→
    85→### Windows (PowerShell)
    86→
    87→Use **PowerShell** (not CMD) in a folder where you want the project. **Docker Desktop** must be running (WSL2 backend recommended).
    88→
    89→```powershell
    90→git clone https://github.com/brokermr810/QuantDinger.git
    91→Set-Location QuantDinger
    92→Copy-Item backend_api_python\env.example -Destination backend_api_python\.env
    93→$key = & python -c "import secrets; print(secrets.token_hex(32))" 2>$null
    94→if (-not $key) { $key = & py -c "import secrets; print(secrets.token_hex(32))" 2>$null }
    95→if (-not $key) { $key = & python3 -c "import secrets; print(secrets.token_hex(32))" 2>$null }
    96→if (-not $key) { Write-Error "Install Python 3 from python.org (tick 'Add to PATH') or use Git Bash with the macOS/Linux block above." }
    97→(Get-Content backend_api_python\.env) -replace '^SECRET_KEY=.*$', "SECRET_KEY=$key" | Set-Content backend_api_python\.env -Encoding utf8
    98→docker-compose up -d --build
    99→```
   100→
   101→If `docker-compose` is not recognized, use **`docker compose`** (space, no hyphen). If Git is missing, install [Git for Windows](https://git-scm.com/download/win).
   102→
   103→### Windows alternative: Git Bash
   104→
   105→If you installed **Git for Windows**, open **Git Bash** and you can use the **macOS / Linux** one-liner above (Bash + `chmod` + `./scripts/generate-secret-key.sh`).
   106→

For prerequisites, configuration details, first-run checks, and troubleshooting, continue to **[Installation & first-time setup](#installation--first-time-setup-docker-compose)** below.

   123→## Use it from an AI agent (Cursor / Claude Code / Codex / MCP)
   124→
   125→QuantDinger ships an **Agent Gateway** at `/api/agent/v1` and a small **MCP server** that wraps it as Model Context Protocol tools. Once you sign in once and issue a token, your AI client can read markets, manage strategies, run backtests, and (paper-only by default) place trades — without ever seeing your exchange keys or your admin JWT.
   126→
   127→> Two safety properties are non-negotiable: every agent call is **audit-logged**, and trading-class tokens are **paper-only by default**. Live execution requires both `paper_only=false` on the token AND `AGENT_LIVE_TRADING_ENABLED=true` on the server.
   128→
   129→### Step 1 — Get an agent token (two paths, your choice)
   130→
   131→The MCP client and the wiring in Step 2 are **identical** for both paths — only the value of `QUANTDINGER_BASE_URL` changes.
   132→
   133→**Path A · Hosted ([ai.quantdinger.com](https://ai.quantdinger.com)) — try it in 30 seconds.** Sign up → open **Sidebar → Agent Tokens** → **Issue Token**. The hosted instance is locked to `paper_only=true` and the **T** (Trading) scope is rejected at issuance — agents can read markets, manage strategies in your tenant, and run backtests, but never route real-money orders. Set `QUANTDINGER_BASE_URL=https://ai.quantdinger.com`. Best for: trying QuantDinger from Cursor / Claude Code without installing anything; demos; research notebooks against shared datasets.
   134→
   135→**Path B · Self-hosted (this repo) — production / private data / live trading.** After the [Try in 2 minutes](#try-in-2-minutes) Docker bring-up, log in as admin and open **Sidebar → Agent Tokens** (or `http://localhost:8888/#/agent-tokens`). You decide scopes (incl. **T**), market/instrument allowlists, rate limits, and whether `AGENT_LIVE_TRADING_ENABLED=true` is ever flipped. Set `QUANTDINGER_BASE_URL=http://localhost:8888` (or your LAN URL). Best for: anyone with their own exchange keys, anyone with private strategies/data, teams behind a VPN, or anyone who eventually wants live execution.
   136→
   137→In either path:
   138→
   139→1. Click **Issue Token** → name it (`cursor-mcp`, `claude-research`, …).
   140→2. Pick scopes — start with **R + B** (read + backtest); add **W** to let the agent create/edit strategies.
   141→3. Copy the token **once** — the dialog shows the full string once; the server only keeps a SHA-256 hash.
   142→
   143→Prefer the CLI? See [`docs/agent/AGENT_QUICKSTART.md`](docs/agent/AGENT_QUICKSTART.md) for the equivalent `curl`.
   144→
   145→### Step 2 — Wire the MCP server into your AI client
   146→
   147→The MCP server lives in [`mcp_server/`](mcp_server/). Two transports work everywhere:
   148→
   149→**A. Local stdio (Cursor, Claude Code, Codex desktop, etc.)** — the server is published on PyPI as [`quantdinger-mcp`](https://pypi.org/project/quantdinger-mcp/). Drop this into `.cursor/mcp.json`, `~/.config/claude/claude_desktop_config.json`, or your client's equivalent (template: [`docs/agent/cursor-mcp.example.json`](docs/agent/cursor-mcp.example.json)):
   150→
   151→```json
   152→{
   153→  "mcpServers": {
   154→    "quantdinger": {
   155→      "command": "uvx",
   156→      "args": ["quantdinger-mcp"],
   157→      "env": {
   158→        "QUANTDINGER_BASE_URL":    "http://localhost:8888",
   159→        "QUANTDINGER_AGENT_TOKEN": "qd_agent_xxxxxxxx"
   160→      }
   161→    }
   162→  }
   163→}
   164→```
   165→
   166→`uvx` ([install uv](https://docs.astral.sh/uv/getting-started/installation/)) downloads + caches the package on first run; no virtualenv setup. If you prefer pip:
   167→
   168→```bash
   169→pip install quantdinger-mcp
   170→# then use {"command": "quantdinger-mcp", "args": []}
   171→```
   172→
   173→For Claude Code's CLI helper:
   174→
   175→```bash
   176→claude mcp add quantdinger \
   177→  --env QUANTDINGER_BASE_URL=http://localhost:8888 \
   178→  --env QUANTDINGER_AGENT_TOKEN=qd_agent_xxxxxxxx \
   179→  -- uvx quantdinger-mcp
   180→```
   181→
   182→**B. Remote HTTP (cloud agents like OpenClaw / NanoBot, browser IDEs, anything that can't spawn subprocesses)** — run the MCP server as a long-lived service, then point clients at the URL:
   183→
   184→```bash
   185→QUANTDINGER_BASE_URL=https://your-host \
   186→QUANTDINGER_AGENT_TOKEN=qd_agent_xxxxxxxx \
   187→QUANTDINGER_MCP_TRANSPORT=streamable-http \
   188→QUANTDINGER_MCP_HOST=0.0.0.0 \
   189→QUANTDINGER_MCP_PORT=7800 \
   190→quantdinger-mcp
   191→# clients connect to http://your-host:7800
   192→```
   193→
   194→Use `QUANTDINGER_MCP_TRANSPORT=sse` instead for clients that only speak the older SSE transport. Put a reverse proxy in front for TLS and IP allowlisting.
   195→
   196→### Step 3 — Talk to your agent
   197→
   198→Restart the IDE, then ask things like:
   199→
   200→- *"Pull the last 90 daily candles for BTC/USDT and tell me what the regime detector says."*
   201→- *"Backtest the 20/60 SMA crossover on ETH/USDT 4h between 2024-01-01 and 2024-06-30 and stream the result as it runs."*
   202→- *"Create a strategy named **eth-trend-bot**, use the indicator I just designed, leave it in `stopped` state."*
   203→
   204→Long-running jobs (`/api/agent/v1/jobs/{id}/stream`) are exposed as SSE so the agent can react to partial results without polling. Every call shows up under **Agent Tokens → Audit log** with route, scope class, status code, and duration.

   212→## Product overview
   213→
   214→QuantDinger is a **self-hosted** quantitative OS: **AI-assisted research**, **Python-native strategies** (`IndicatorStrategy` + `ScriptStrategy`), **backtesting**, and **live trading** (crypto, IBKR, MT5)—with optional multi-user roles, notifications, credits, and USDT billing. It replaces a patchwork of charts, notebooks, bots, and disconnected LLM chats with **one Compose stack** and **your** credentials in Postgres + `.env`.
   215→
   216→| Typical DIY stack | QuantDinger |
   217→|-------------------|-------------|
   218→| Chat AI separate from execution | Analysis, NL→code, backtests, and execution in one product |
   219→| Many tools wired by hand | Nginx + Vue UI, Flask API, workers, exchange/LLM adapters |
   220→| Opaque SaaS keys | Your infra, your exchange keys, your LLM keys |
   221→
   222→**Audience:** traders and quants, Python strategy authors, small teams building internal or commercial trading products.

   252→## Features at a glance
   253→
   254→- **Research & AI** — Multi-LLM analysis, watchlists, analysis history; optional ensemble/calibration; NL→indicator/strategy; post-backtest AI hints; Polymarket as a **research** workflow. **[Agent Gateway + MCP](#use-it-from-an-ai-agent-cursor--claude-code--codex--mcp)** for Cursor / Claude Code / Codex.
   255→- **Build** — `IndicatorStrategy` (dataframe signals, chart overlays) and `ScriptStrategy` (`on_bar`, explicit orders); professional chart UI.
   256→- **Validate** — Server-side backtests, metrics, equity curves, strategy snapshots.
   257→- **Operate** — Crypto execution, quick trade, IBKR / MT5, notifications (Telegram, email, SMS, Discord, webhooks).
   258→- **Platform** — Docker Compose, Postgres, Redis, OAuth, multi-user patterns, credits / membership / USDT billing toggles.
   259→
   260→## Architecture
   261→
   262→**Stack:** Nginx serves the prebuilt Vue app (`frontend/dist`); **Flask** API runs strategy/AI/billing services; **PostgreSQL** holds state; **Redis** backs workers. Exchanges, brokers, LLMs, and payments plug in through env-driven adapters. Crypto **market data** and **order execution** paths are separated by design.
   263→
   264→**Runtime (short):** data feeds → backtest/strategy engine → live runtime → exchange adapters; pending orders dispatched per venue.

   322→## Installation & first-time setup (Docker Compose)
   323→
   324→**Fast path:** [Try in 2 minutes](#try-in-2-minutes) first. The steps below are the full checklist (same outcome, more detail).
   325→
   326→This section mirrors a typical “local deploy” path: **prepare the host → obtain the code → configure secrets → start the stack → verify → harden → optionally wire AI**. Node.js is **not** required: the repo ships a **prebuilt** UI under `frontend/dist` and Nginx serves it inside the `frontend` container.
   327→
   328→### Prerequisites
   329→
   330→| Item | Notes |
   331→|------|--------|
   332→| [Docker](https://docs.docker.com/get-docker/) + Docker Compose v2 | Used for Postgres, Redis, API, and static UI. |
   333→| `git` | To clone this repository. |
   334→| Ports (defaults) | `8888` (web), `5000` (API, bound to **127.0.0.1**), `5432` / `6379` (DB/Redis, loopback by default). Change via root `.env` if they collide. |
   335→| Disk | Postgres volume grows with users, strategies, and logs; plan a few GB minimum for serious use. |
   336→
   337→### 1) Clone the repository
   338→
   339→```bash
   340→git clone https://github.com/brokermr810/QuantDinger.git
   341→cd QuantDinger
   342→```
   343→
   344→### 2) Create backend configuration (mandatory)
   345→
   346→```bash
   347→cp backend_api_python/env.example backend_api_python/.env
   348→```
   349→
   350→Almost all runtime behavior is driven by **`backend_api_python/.env`** (database URL, admin user, LLM keys, workers, billing toggles, etc.). The optional **repository root** `.env` only adjusts Compose-level concerns such as **ports** and **image mirrors** (`IMAGE_PREFIX`).
   351→
   352→### 3) Set `SECRET_KEY` before the first boot (mandatory)
   353→
   354→The API **refuses to start** if `SECRET_KEY` is still the placeholder from `env.example`. This blocks accidental insecure deployments.
   355→
   356→**Linux / macOS** (recommended):
   357→
   358→```bash
   359→./scripts/generate-secret-key.sh
   360→```
   361→
   362→The script overwrites the `SECRET_KEY=` line in `backend_api_python/.env` using Python’s `secrets` module.
   363→
   364→**Manual** (any OS): generate a long random string (for example 64 hex chars) and set `SECRET_KEY=...` in `backend_api_python/.env`.
   365→
   366→### 4) Start the stack
   367→
   368→```bash
   369→docker-compose up -d --build
   370→```
   371→
   372→Services: **`postgres`**, **`redis`**, **`backend`**, **`frontend`** (see `docker-compose.yml` for healthchecks and port mappings).
   373→
   374→### 5) Verify and sign in
   375→
   376→| Check | URL / command |
   377→|--------|----------------|
   378→| Web UI | `http://localhost:8888` (override host/port with `FRONTEND_HOST` / `FRONTEND_PORT` in root `.env` if needed). |
   379→| API health | `http://localhost:5000/api/health` |
   380→| Logs | `docker-compose logs -f backend` |
   381→
   382→Default admin (change immediately in production):
   383→
   384→- **User**: `quantdinger`
   385→- **Password**: `123456` (from `env.example`; override with `ADMIN_USER` / `ADMIN_PASSWORD` in `.env` before first use if you prefer).
   386→
   387→Also set **`FRONTEND_URL`** in `backend_api_python/.env` to the URL users actually use (including `https://` behind a reverse proxy); it affects redirects, CORS-related settings, and some generated links.
   388→
   389→### 6) Optional: enable AI features
   390→
   391→AI analysis, NL→code, and related flows need at least one LLM provider configured. Open `backend_api_python/env.example`, find the **AI / LLM** block, copy the relevant keys into your `.env` (for example `LLM_PROVIDER` + `OPENROUTER_API_KEY`, or another supported provider). Restart the backend after edits.

   393→### 7) Windows notes
   394→
   395→Use **Docker Desktop** (WSL2 backend recommended). From PowerShell in the repo root:
   396→
   397→```powershell
   398→git clone https://github.com/brokermr810/QuantDinger.git
   399→cd QuantDinger
   400→Copy-Item backend_api_python\env.example -Destination backend_api_python\.env
   401→$key = py -c "import secrets; print(secrets.token_hex(32))"
   402→(Get-Content backend_api_python\.env) -replace '^SECRET_KEY=.*$', "SECRET_KEY=$key" | Set-Content backend_api_python\.env -Encoding UTF8
   403→docker-compose up -d --build
   404→```
   405→
   406→If `py` is not on PATH, use `python` or `python3` in the one-liner that generates `$key`. Line endings should remain UTF-8; avoid editors that strip newlines from `.env`.

   408→### Troubleshooting (first boot)
   409→
   410→| Symptom | What to check |
   411→|---------|----------------|
   412→| Backend exits immediately | `SECRET_KEY` still default, or invalid `.env` syntax. Read `docker-compose logs backend`. |
   413→| Blank page or API errors from browser | `FRONTEND_URL` / origins mismatch; API not reachable from the host you opened. |
   414→| Port already in use | Another Postgres, Redis, or local service on `5432` / `6379` / `5000` / `8888`. Adjust variables in root `.env` per `docker-compose.yml`. |
   415→| Many live strategies, “start denied” | Raise `STRATEGY_MAX_THREADS` in `backend_api_python/.env` and restart API (see comments in `env.example`). |

   443→## Minimal Example: Python Indicator Strategy
   444→
   445→This is the kind of Python-native strategy logic QuantDinger is designed for:
   446→
   447→```python
   448→# @param sma_short int 14 Short moving average
   449→# @param sma_long int 28 Long moving average
   450→
   451→sma_short_period = params.get('sma_short', 14)
   452→sma_long_period = params.get('sma_long', 28)
   453→
   454→my_indicator_name = "Dual Moving Average Strategy"
   455→my_indicator_description = f"SMA {sma_short_period}/{sma_long_period} crossover"
   456→
   457→df = df.copy()
   458→sma_short = df["close"].rolling(sma_short_period).mean()
   459→sma_long = df["close"].rolling(sma_long_period).mean()
   460→
   461→buy = (sma_short > sma_long) & (sma_short.shift(1) <= sma_long.shift(1))
   462→sell = (sma_short < sma_long) & (sma_short.shift(1) >= sma_long.shift(1))
   463→
   464→df["buy"] = buy.fillna(False).astype(bool)
   465→df["sell"] = sell.fillna(False).astype(bool)
   466→```
   467→
   468→See full examples:
   469→

   471→- [`docs/examples/multi_indicator_composite.py`](docs/examples/multi_indicator_composite.py)
   472→- [`docs/examples/cross_sectional_momentum_rsi.py`](docs/examples/cross_sectional_momentum_rsi.py)

   503→## Strategy Development Modes
   504→
   505→QuantDinger supports two main strategy authoring models:
   506→
   507→### IndicatorStrategy
   508→
   509→- dataframe-based Python scripts
   510→- `buy` / `sell` signal generation
   511→- chart rendering and signal-style backtests
   512→- best for research, indicator logic, and visual strategy prototyping
   513→
   514→### ScriptStrategy
   515→
   516→- event-driven `on_init(ctx)` / `on_bar(ctx, bar)` scripts
   517→- explicit runtime control with `ctx.buy()`, `ctx.sell()`, `ctx.close_position()`
   518→- best for stateful strategies, execution-oriented logic, and live alignment
   519→
   520→For the full developer workflow, see:
   521→
   522→- [Strategy Development Guide](docs/STRATEGY_DEV_GUIDE.md)
   523→- [Cross-Sectional Strategy Guide](docs/CROSS_SECTIONAL_STRATEGY_GUIDE_EN.md)
   524→- [Strategy Examples](docs/examples/)
   525→
   526→The example scripts live in `docs/examples/` and are kept aligned with the current strategy development guides.

   581→## FAQ
   582→
   583→### Is QuantDinger really self-hosted?
   584→
   585→Yes. The default deployment model is your own Docker Compose stack with your own database, Redis instance, credentials, and environment configuration.
   586→
   587→### Is QuantDinger only for crypto trading?
   588→
   589→No. Crypto is a major focus, but the platform also includes IBKR workflows for US stocks, MT5 workflows for forex, and Polymarket research support.
   590→
   591→### Can I write strategies directly in Python?
   592→
   593→Yes. QuantDinger supports both dataframe-style `IndicatorStrategy` development and event-driven `ScriptStrategy` development. You can also use AI to generate a starting point and then edit it yourself.
   594→
   595→### Is this a research tool or a live trading platform?
   596→
   597→It is both. QuantDinger is built to connect AI research, charting, strategy development, backtesting, quick trade flows, and live execution operations in one system.
   598→
