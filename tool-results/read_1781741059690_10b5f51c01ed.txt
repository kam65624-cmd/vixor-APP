    10→    10→## 1. Executive Summary
    11→    11→
    12→    12→QuantDinger is a **self-hosted, local-first AI quant operating system** that bundles,
    13→    13→in a single Docker Compose stack, the full vertical slice of a retail/hobbyist
    14→    14→algorithmic trading platform:
    15→    15→
    16→    16→* Flask 3.1 backend (gunicorn, single-process + gthread, Postgres + Redis)
    17→    17→* Pre-built **Vue.js SPA** served by Nginx (Vue source lives in a private repo;
    18→    18→  this open-source tree only ships `frontend/dist/`)
    19→    19→* **Python strategy engine** with two authoring models:
    20→    20→  * `IndicatorStrategy` (dataframe-based, signal-style) — the primary model
    21→    21→  * `ScriptStrategy` (event-driven, `on_init(ctx)` + `on_bar(ctx, bar)` with
    22→    22→    `ctx.buy/sell/close_position`) — for live execution
    23→    23→* **Safe code execution** sandbox (`safe_exec.py`): regex + AST validation,
    24→    24→  restricted `__builtins__`, whitelisted imports (numpy/pandas/math/json/etc.),
    25→    25→  SIGALRM/ctypes-based timeout, optional multiprocessing subprocess isolation.
    26→    26→* **Backtest engine** (`backtest.py`, ~5K lines) with multi-timeframe (1m/5m)
    27→    27→  precision mode for crypto, long/short, leverage, commission/slippage,
    28→    28→  trailing stops, equity curve, trade ledger, persisted to Postgres.
    29→    29→* **Live trading** via direct REST clients (no ccxt for trade routing) for
    30→    30→  Binance (spot+futures), OKX, Bitget, Bybit, Coinbase Exchange, Kraken
    31→    31→  (spot+futures), KuCoin (spot+futures), Gate (spot+futures), Deepcoin, HTX,
    32→    32→  plus IBKR (US stocks via TWS/IB Gateway) and MT5 (Forex, Windows-only).
    33→    33→* **AI / Agent Gateway v1** (`/api/agent/v1`): capability-class scoped token
    34→    34→  auth (R/W/B/N/C/T), async job runner with SSE progress streaming,
    35→    35→  Idempotency-Key, audit log, paper-only trading by default, hard SaaS-mode
    36→    36→  guard that rejects T-scope tokens at issuance.
    37→    37→* **MCP server** (`mcp_server/`, also published to PyPI as `quantdinger-mcp`)
    38→    38→  exposing a curated read + backtest subset of the Agent Gateway as MCP tools
    39→    39→  for Cursor / Claude Code / Codex / OpenClaw / NanoBot. Supports stdio / sse
    40→    40→  / streamable-http transports.
    41→    41→* **Experiment orchestration** layer (`app/services/experiment/`): rule-based
    42→    42→  market regime detection, structured (grid/random) parameter tuning, and
    43→    43→  multi-round LLM-driven optimization with structured prompts.
    44→    44→* **Reflection / self-calibration loop**: a background worker validates past
    45→    45→  AI decisions against actual price outcomes, then re-calibrates BUY/SELL/HOLD
    46→    46→  score thresholds per market.
    47→    47→* **Notifications**: in-app + Email (SMTP) + Telegram (Bot API) + Twilio SMS
    48→    48→  + Discord webhook + generic webhook + browser push.
    49→    49→* **Multi-tenancy with billing**: credits, VIP plans, USDT-TRC20 on-chain
    50→    50→  payment (HD-derived per-order address, TronGrid reconciliation), OAuth
    51→    51→  (Google/GitHub), email verification, brute-force protection.
    52→    52→* **Strategy community marketplace**: indicator publish/purchase/comments/
    53→    53→  reviews with admin moderation.
    54→    54→* **Polymarket prediction-market module**: cache + AI divergence analysis +
    55→    55→  asset-level signal derivation.
    56→    56→
    57→    57→Total scale: **~25 backend route files, ~40 service files, ~1,117 lines of SQL
    58→    58→schema (30+ tables), ~10 live-trading adapters, 10 data sources, 9 data
    59→    59→providers, 11 tests files, 1 MCP server (11 tools)**. Frontend ships as ~30
    60→    60→chunked JS bundles (~9MB+ minified) and supports 9 locales (zh-CN, zh-TW,
    61→    61→en-US, ko-KR, ja-JP, fr-FR, de-DE, vi-VN, th-TH, ar-SA).

    96→    96→### 2.2 Compose topology
    97→    97→
    98→    98→```
    99→    99→Browser → (host Nginx 80/443) → frontend:80 (Nginx in container)
   100→   100→                                  ├── serves dist/
   101→   101→                                  └── /api/* → backend:5000 (gunicorn)
   102→   102→                                                   ├── postgres:5432 (pool 5–50)
   103→   103→                                                   └── redis:6379 (LRU 128MB)
   104→   104→```
   105→   105→
   106→   106→* `BACKEND_URL` env var templated into `nginx.conf.template` via `entrypoint.sh`
   107→   107→  (custom envsubst on a strict shell-format list so nginx's own `$host` etc.
   108→   108→  stay literal).
   109→   109→* `BACKEND_PORT`, `DB_PORT` default to `127.0.0.1:5000/5432` so only 80/443 are
   110→   110→  public.
   111→   111→* `IMAGE_PREFIX` allows swapping Docker Hub for China mirrors
   112→   112→  (`docker.m.daocloud.io/library/`, `docker.xuanyuan.me/library/`).
   113→   113→* `ALLOW_LOCAL_DESKTOP_BROKERS=true` (default) gates IBKR/MT5 routes — set to
   114→   114→  `false` on SaaS cloud.
   115→   115→
   116→   116→### 2.3 Process / thread model
   117→   117→
   118→   118→* `create_app()` boots:
   119→   119→  * `init_database()` (verifies Postgres connection)
   120→   120→  * `ensure_admin_exists()` (creates admin user from `ADMIN_USER` / `ADMIN_PASSWORD`)
   121→   121→  * `register_routes(app)` — 22 blueprints + the agent_v1 sub-package
   122→   122→  * Background threads (all daemon, all in-process, no Celery / no RQ):
   123→   123→    * `PendingOrderWorker` (polls `pending_orders` every 1s, batch 50)
   124→   124→    * `PortfolioMonitor` (scheduled AI analysis on manual positions)
   125→   125→    * `UsdtOrderWorker` (on-chain USDT payment reconciliation)
   126→   126→    * `PolymarketWorker` (caches prediction-market data)
   127→   127→    * `AICalibrationService.start_ai_calibration_worker` (offline threshold tuning)
   128→   128→    * `ReflectionService.start_reflection_worker` (daily validation cycle)
   129→   129→    * `restore_running_strategies()` (re-spawns `IndicatorStrategy` threads)
   130→   130→* `TradingExecutor` is a singleton; each running strategy owns its own thread.
   131→   131→* Gunicorn: 1 worker × 8 threads (default). All background work runs inside
   132→   132→  that single worker process — multi-worker would duplicate background threads.
   133→   133→
   134→   134→### 2.4 Two-topology design
   135→   135→
   136→   136→A single binary serves both **self-hosted** (1 tenant, full feature set) and
   137→   137→**SaaS/hosted** (N tenants, T-scope hard-blocked at issuance) modes. The
   138→   138→selector is the env var `QUANTDINGER_DEPLOYMENT_MODE`
   139→   139→(`saas`/`hosted`/`shared`/`multitenant`/`multi-tenant`). When in SaaS mode:
   140→   140→
   141→   141→* `POST /api/agent/v1/admin/tokens` rejects any payload containing scope `T`
   142→   142→  with HTTP 403 (loud, not silent downgrade).
   143→   143→* `paper_only` is force-pinned to `True` on every issued token.
   144→   144→* `AGENT_LIVE_TRADING_ENABLED` is irrelevant because no token can have T.
   145→   145→
   146→   146→Tested by `tests/test_agent_v1_saas_guard.py` (13 cases).

   318→   318→## 4. Strategy Engine Deep Dive
   319→   319→
   320→   320→This is the most valuable part of QuantDinger for VIXOR. The system supports
   321→   321→**two distinct authoring models** that share storage but execute differently.
   322→   322→
   323→   323→### 4.1 Authoring model A — IndicatorStrategy (primary)
   324→   324→
   325→   325→* **Language**: pure Python (pandas + numpy).
   326→   326→* **Convention**: user code receives `df` (OHLCV DataFrame) and must:
   327→   327→  1. Compute boolean `df['buy']` and `df['sell']` columns (edge-triggered
   328→   328→     recommended — `raw & ~raw.shift(1)`).
   329→   329→  2. Build an `output` dict with `name`, `plots` (overlay/non-overlay series),
   330→   330→     `signals` (buy/sell marks with text + color).
   331→   331→  3. Optionally declare metadata via comments:
   332→   332→     ```python
   333→   333→     # @strategy stopLossPct 0.03
   334→   334→     # @strategy takeProfitPct 0.06
   335→   335→     # @strategy entryPct 1
   336→   336→     # @strategy tradeDirection long
   337→   337→     # @param rsi_len int 14 RSI period
   338→   338→     ```
   339→   339→* **`@strategy` keys** (parsed by `StrategyConfigParser`): `stopLossPct`,
   340→   340→  `takeProfitPct`, `entryPct`, `trailingEnabled`, `trailingStopPct`,
   341→   341→  `trailingActivationPct`, `tradeDirection` (long|short|both).
   342→   342→* **`@param` keys** (parsed by `IndicatorParamsParser`): allow runtime
   343→   343→  parameterization (int/float/bool/str) — surfaced in the IDE for sliders.
   344→   344→* **Backtest path**: `BacktestService.run(indicator_code, market, symbol, ...)`
   345→   345→  → `safe_exec_with_validation(code)` over an `exec_env` containing
   346→   346→  `np`/`pd`/`df` → extract `df['buy']`/`df['sell']` → simulate bar-by-bar
   347→   347→  with optional multi-timeframe precision (1m exec under 1D signal for
   348→   348→  crypto, ≤15 days; 5m exec for ≤1 year).
   349→   349→* **Live path**: `TradingExecutor.start_strategy(id)` spawns a daemon thread
   350→   350→  that polls K-line every `decide_interval` seconds, re-runs the indicator
   351→   351→  code, derives latest-bar signals, enqueues `pending_orders` rows.
   352→   352→
   353→   353→### 4.2 Authoring model B — ScriptStrategy (event-driven)
   354→   354→
   355→   355→* **Language**: pure Python (numpy + pandas).
   356→   356→* **Convention**: user code defines `on_init(ctx)` (optional) and
   357→   357→  `on_bar(ctx, bar)` (required). The `ctx` (`StrategyScriptContext`) exposes:
   358→   358→  * `ctx.position` — `ScriptPosition` with `side`/`size`/`entry_price`/
   359→   359→    `direction` (`+1`/`-1`/`0`), supports `bool()`/`int()`/`float()` and rich
   360→   360→    comparison operators.
   361→   361→  * `ctx.balance`, `ctx.equity`, `ctx.current_index`
   362→   362→  * `ctx.bars(n=1)` — list of recent `ScriptBar`s (open/high/low/close/volume)
   363→   363→  * `ctx.param(name, default)` — typed parameter access
   364→   364→  * `ctx.log(msg)` — append to in-process log buffer
   365→   365→  * `ctx.buy(price=None, amount=None)` / `ctx.sell(...)` / `ctx.close_position()`
   366→   366→    — append to `_orders` queue, consumed by the runtime after each bar.
   367→   367→* **Compile**: `compile_strategy_script_handlers(code)` runs
   368→   368→  `safe_exec_with_validation` to extract the two callables.
   369→   369→* **Live path**: `TradingExecutor` advances `ctx.current_index` bar-by-bar
   370→   370→  in real time, calls `on_bar(ctx, bar)`, drains `_orders` into the
   371→   371→  `pending_orders` queue with `signal_type` derived from the order action
   372→   372→  and current position direction (e.g. `open_long` / `add_long` /
   373→   373→  `close_long` / `open_short` / `add_short` / `close_short`).
   374→   374→* **Backtest path**: `_run_script_strategy` in `BacktestService` mirrors this
   375→   375→  flow for historical simulation.
   376→   376→
   377→   377→### 4.3 Safe execution sandbox (`app/utils/safe_exec.py`)
   378→   378→
   379→   379→Three layers of defense:
   380→   380→
   381→   381→1. **Static validation** (`validate_code_safety`):
   382→   382→   * **Regex blacklist** for dangerous patterns: `os.system`, `subprocess`,
   383→   383→     `__import__`, `eval(`/`exec(`/`compile(`/`open(`, `getattr(`/`setattr(`,
   384→   384→     `__dict__`/`__class__`/`__subclasses__`/`__globals__`/`__code__`,
   385→   385→     `globals(`/`vars(`/`dir(`/`breakpoint(`, plus `import os|sys|subprocess|
   386→   386→     shutil|signal|resource|pymysql|sqlite3|psycopg2|sqlalchemy|requests|
   387→   387→     urllib|http|socket|ftplib|telnetlib|smtplib|ssl|pickle|marshal|shelve|
   388→   388→     ctypes|cffi|multiprocessing|threading|concurrent|asyncio|importlib|imp|
   389→   389→     builtins|code|codeop|runpy|tempfile|glob|pathlib|io`.
   390→   390→   * **AST walk** (fail-closed if parse fails): reject `ast.Import` /
   391→   391→     `ast.ImportFrom` for any module root not in `SAFE_IMPORT_MODULES` =
   392→   392→     `{numpy, pandas, math, json, datetime, time, collections, functools,
   393→   393→     itertools, statistics, decimal, fractions, operator, copy}`. Reject
   394→   394→     `ast.Call` to dangerous call names (`eval`/`exec`/`compile`/`__import__`/
   395→   395→     `getattr`/`setattr`/`delattr`/`globals`/`vars`/`dir`/`breakpoint`/`open`/
   396→   396→     `input`/`exit`/`quit`) and attribute access on dangerous modules. Reject
   397→   397→     `ast.Attribute` for dangerous dunders.
   398→   398→2. **Restricted `__builtins__`**: only a whitelisted set is available — types
   399→   399→   (`bool`/`int`/`float`/`str`/`list`/`dict`/`set`/`tuple`/`frozenset`/...),
   400→   400→   math (`abs`/`round`/`pow`/`min`/`max`/`sum`), iteration
   401→   401→   (`len`/`enumerate`/`zip`/`map`/`filter`/`sorted`/`reversed`/`iter`/`next`/
   402→   402→   `all`/`any`), strings (`repr`/`chr`/`ord`/`format`/`bin`/`hex`/`oct`),
   403→   403→   type checks (`isinstance`/`issubclass`/`hasattr`/`callable`), `print`,
   404→   404→   safe exceptions (`Exception`/`ValueError`/`TypeError`/...),
   405→   405→   `staticmethod`/`classmethod`/`property`/`super`/`object`, constants
   406→   406→   (`True`/`False`/`None`/`Ellipsis`/`NotImplemented`). `__import__` is
   407→   407→   replaced with `_make_safe_import()` that only allows whitelisted roots.
   408→   408→3. **Timeout + memory**:
   409→   409→   * **Cross-platform timeout** via `timeout_context(seconds)`:
   410→   410→     * Unix main thread: `signal.SIGALRM`
   411→   411→     * Else (Windows or non-main thread): `threading.Timer` + ctypes
   412→   412→       `PyThreadState_SetAsyncExc` to inject `TimeoutError` into the target
   413→   413→       thread.
   414→   414→   * Optional `RLIMIT_AS` memory cap on Linux when
   415→   415→     `SAFE_EXEC_ENABLE_RLIMIT=true` (default false).
   416→   416→4. **Subprocess isolation** (`safe_exec_isolated`): optional mode that runs
   417→   417→   the user code in a `multiprocessing.Process` with its own memory space,
   418→   418→   `RLIMIT_AS` enforced, pickle-serialized result pipe. Used for the
   419→   419→   highest-isolation path (heavy indicator runs).
   420→   420→
   421→   421→### 4.4 Backtest engine internals
   422→   422→
   423→   423→* **Candle-path simulation**: for each bar, the engine infers a 4-point
   424→   424→  price path — bullish bar = `open → low → high → close` (dip then rally),
   425→   425→  bearish = `open → high → low → close` (rally then dip). This lets SL/TP
   426→   426→  trigger intra-bar with realistic ordering.
   427→   427→* **State machine**: `position ∈ {-size, 0, +size}` with `position_type ∈
   428→   428→  {None, 'long', 'short'}`. Signals are queued, executed at next bar's open
   429→   429→  price with slippage applied (long buys above open, short sells below).
   430→   430→* **Risk features**: fixed SL/TP, trailing stop (activates after
   431→   431→  `trailingActivationPct`, trails by `trailingStopPct`), liquidation
   432→   432→  detection (capital < `min_capital_to_trade` → `is_liquidated=True`).
   433→   433→* **Trade-direction modes**: `long` (long-only), `short` (short-only),
   434→   434→  `both` (close-then-reverse on opposite signal).
   435→   435→* **Multi-timeframe (MTF)**: when `enable_mtf=True` and market is crypto:
   436→   436→  * ≤15 days → execute on 1m bars (max ~21,600 candles)
   437→   437→  * 16–365 days → execute on 5m bars (max ~105,120 candles)
   438→   438→  * >1 year → MTF disabled, fall back to native timeframe
   439→   439→* **Persistence**: `qd_backtest_runs` (config snapshot, code_hash, result_json),
   440→   440→  `qd_backtest_trades` (per-trade record), `qd_backtest_equity_points`
   441→   441→  (equity curve samples). `run_type ∈ {indicator, strategy_indicator,
   442→   442→  strategy_script}`.
   443→   443→* **Storage schema auto-migration** on first use (`ensure_storage_schema()`)
   444→   444→  — adds columns / creates tables if missing, so the system is resilient to
   445→   445→  partial schema states.
   446→   446→
   447→   447→### 4.5 Live execution flow
   448→   448→
   449→   449→```
   450→   450→TradingExecutor.start_strategy(id)
   451→   451→  ├── load strategy row from qd_strategies_trading
   452→   452→  ├── spawn daemon thread
   453→   453→  └── loop:
   454→   454→        ├── fetch latest K-line (cached 10s)
   455→   455→        ├── fetch current price (KlineService)
   456→   456→        ├── run indicator code via safe_exec
   457→   457→        ├── extract latest-bar signals (df['buy'] / df['sell'])
   458→   458→        ├── dedup via (strategy_id, symbol, signal_type, signal_ts) → skip if seen in 2× timeframe window
   459→   459→        ├── enforce state machine: flat → open_long/open_short; long → add_long/reduce_long/close_long; short → add_short/reduce_short/close_short
   460→   460→        ├── compute stake amount from entry_pct × equity × leverage
   461→   461→        ├── INSERT into pending_orders (status='pending')
   462→   462→        ├── SignalNotifier.notify_signal() — fire Telegram/Email/etc.
   463→   463→        └── sleep decide_interval seconds
   464→   464→
   465→   465→PendingOrderWorker (separate thread):
   466→   466→  ├── poll pending_orders WHERE status='pending' every 1s
   467→   467→  ├── claim batch (row-level lock via SELECT FOR UPDATE)
   468→   468→  ├── create_client(exchange_config, market_type) via factory
