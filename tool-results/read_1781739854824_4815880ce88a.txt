     7→## V3.1.0 (2026-05-02) — AI Agent Gateway / MCP HTTP / SSE 进度流 / Admin UI
     8→
     9→把 QuantDinger 从「只服务人类用户的 Web 产品」扩展成「同时面向人类和 AI Agent 的两栈产品」。给 OpenClaw / NanoBot / Claude Code / Cursor / Codex 这类 Agent 运行时配齐了：受控的 HTTP 网关、按 Scope 的细粒度授权、异步任务 + 实时进度、MCP 接入、Admin 后台运维面板，以及一份机器可读的契约（OpenAPI 3.0）。**所有 Agent 入口默认拒绝实盘交易**——T 类（Trading）即便给到 Agent，也走纸面订单簿，需要管理员显式开启服务器级开关后才可能走真实交易所。
    10→
    11→### 🚀 New Features
    12→
    13→#### Agent Gateway（`/api/agent/v1`）
    14→全新的、与人类 JWT 完全隔离的机器对机器 API：
    15→- **Token 模型**：管理员一次性签发 `qd_agent_xxxx` 令牌，存库时只保留 SHA-256 哈希；支持自定义 scopes (`R / W / B / N / C / T`)、市场白名单、品种白名单、`paper_only`、速率上限、过期时间。
    16→- **Capability Classes**：每个端点声明唯一一个 risk class —— **R**(Read) / **W**(Workspace write) / **B**(Backtest) / **N**(Notify) / **C**(Credentials, admin only) / **T**(Trading, paper-only by default)。
    17→- **审计日志**：每一次 Agent 调用（成功、被拒、429）都追加到 `qd_agent_audit`，含路由、scope class、状态码、耗时与脱敏后的请求/响应摘要。
    18→- **速率限制 + 幂等**：基于 token 的进程内滑动窗口；W/B/T 类支持 `Idempotency-Key` 头，重复 key 直接返回原始 job，不再重复执行。
    19→- **异步任务**：长任务（回测、实验流水线、AI 优化）通过进程内 `ThreadPoolExecutor` 入队，写入 `qd_agent_jobs`，客户端走「提交 → 轮询 / SSE」模式；workers 数和实盘开关都走 env 控制。
    20→- **Tenant 隔离**：`token → user_id → 资源`；任何 Agent 都看不到其他用户的策略、订单、审计或任务。
    21→
    22→实现的端点（与 `docs/agent/agent-openapi.json` 一一对应）：
    23→| 类别 | 路径 | Class | 说明 |
    24→|---|---|---|---|
    25→| Health | `GET /health` · `GET /whoami` | – / R | 公开存活 / token 自省 |
    26→| Markets | `GET /markets` · `/markets/{m}/symbols` · `/klines` · `/price` | R | 行情 |
    27→| Strategies | `GET /strategies` · `GET/POST/PATCH /strategies/{id}` | R / W | 状态切到 `running` 需 T |
    28→| Backtests | `POST /backtests` | B | 异步，返回 `job_id` |
    29→| Experiments | `POST /experiments/{regime/detect, pipeline, structured-tune, ai-optimize}` | B | regime 同步、其余异步 |
    30→| Jobs | `GET /jobs` · `GET /jobs/{id}` · `GET /jobs/{id}/stream` | R | 列表 / 单查 / **SSE 实时流** |
    31→| Portfolio | `GET /portfolio/positions` · `/portfolio/paper-orders` | R | 持仓 / 纸面成交 |
    32→| Quick-Trade | `POST /quick-trade/orders` · `POST /quick-trade/kill-switch` | T | 默认走纸面簿 |
    33→| Admin | `POST/GET /admin/tokens` · `DELETE /admin/tokens/{id}` · `GET /admin/audit` | – | 仅人类 JWT |
    34→
    35→#### SSE 实时进度（`GET /api/agent/v1/jobs/{id}/stream`）
    36→长任务（`ai-optimize` / `structured-tune` / 多轮回测流水线）现在能让 LLM 客户端「边跑边看」：
    37→- 帧类型：`snapshot`（首帧给基线）→ `progress`（每次 runner `on_progress` 触发）→ `ping`（~15s 心跳，防代理掐线）→ `result`（终态后立刻收尾）。
    38→- 断点续传：`?since=<seq>` 或标准 `Last-Event-ID` 头。
    39→- 任务已结束时直接给 `snapshot + result` 后关闭，客户端无需写两套逻辑。
    40→- Runner 接入约定：`runner(payload, on_progress)` 第二参数自动被探测到，事件同时投递给 SSE 订阅者并写入 `qd_agent_jobs.progress` JSONB（断线重连可读取最新快照）。
    41→
    42→#### MCP Server（`mcp_server/` —— 已发布到 PyPI: [`quantdinger-mcp`](https://pypi.org/project/quantdinger-mcp/)）
    43→独立 Python 包，把 Agent Gateway 的 R / B 子集包成 Model Context Protocol 工具：
    44→- 一行装好（任意机器，不用 clone 仓库）：`uvx quantdinger-mcp` / `pipx install quantdinger-mcp` / `pip install quantdinger-mcp`。
    45→- 三种 transport，由环境变量 `QUANTDINGER_MCP_TRANSPORT` 选：
    46→  - `stdio`（默认）—— 桌面 IDE（Cursor / Claude Code）以子进程启动
    47→  - `sse` —— 仅支持 SSE 的客户端
    48→  - `streamable-http` —— 新版 MCP HTTP 协议，云端 Agent / 远程 IDE 直连
    49→- HTTP 模式额外读 `QUANTDINGER_MCP_HOST` / `QUANTDINGER_MCP_PORT`。
    50→- 永远只接 Agent token，**绝不要写人类 JWT 或交易所 Key**。
    51→
    52→#### 前端 Admin UI：Agent Tokens 面板（仅 admin）
    53→集成进现有 Vue 后台（与「用户管理」「系统设置」并列）：
    54→- 路由 `/agent-tokens`，权限 `permission: ['admin']`。
    55→- **Tokens 标签**：列表（含彩色 scope tag、market 白名单、paper-only / live-eligible 状态、最后使用时间）+ 撤销按钮。
    56→- **签发弹窗**：scope 多选、市场/品种白名单、速率、过期天数、`paper_only` 开关；勾 T 但关 paper-only 时给红色警告提示需要服务器端 `AGENT_LIVE_TRADING_ENABLED=true`。
    57→- **Reveal 弹窗**：完整 token **只显示一次**，自带复制到剪贴板。
    58→- **Audit 标签**：method / route / scope class / status / 耗时；status 用色阶（5xx 红、429 橙、4xx 火、2xx 绿）。
    59→- i18n：`en-US` + `zh-CN` 各加约 30 个 `agentTokens.*` key，其它语言走英文 fallback。

    93→### 🗄️ Database Migration
    94→
    95→本版新增 4 张表 + 1 个 JSONB 列，全部由 `agent_auth._ensure_schema` 在第一次接到 Agent 请求时**自动幂等创建**，所以**已运行的部署什么都不做也能正常用**。但建议在升级时统一显式执行下面的 SQL，确保索引齐全：
    96→
    97→```sql
    98→-- ============================================================
    99→-- QuantDinger V3.1.0 Database Migration
   100→-- Agent Gateway: tokens / async jobs / audit / paper orders
   101→-- ============================================================
   102→
   103→-- 1. Agent tokens (one row per issued token; only the SHA-256 hash is stored)
   104→CREATE TABLE IF NOT EXISTS qd_agent_tokens (
   105→    id SERIAL PRIMARY KEY,
   106→    user_id INTEGER NOT NULL REFERENCES qd_users(id) ON DELETE CASCADE,
   107→    name VARCHAR(80) NOT NULL,
   108→    token_prefix VARCHAR(24) NOT NULL,
   109→    token_hash VARCHAR(128) NOT NULL,
   110→    scopes TEXT NOT NULL DEFAULT 'R',
   111→    markets TEXT NOT NULL DEFAULT '*',
   112→    instruments TEXT NOT NULL DEFAULT '*',
   113→    paper_only BOOLEAN NOT NULL DEFAULT TRUE,
   114→    rate_limit_per_min INTEGER NOT NULL DEFAULT 60,
   115→    status VARCHAR(20) NOT NULL DEFAULT 'active',
   116→    expires_at TIMESTAMP,
   117→    last_used_at TIMESTAMP,
   118→    created_at TIMESTAMP DEFAULT NOW()
   119→);
   120→CREATE UNIQUE INDEX IF NOT EXISTS idx_agent_tokens_hash   ON qd_agent_tokens(token_hash);
   121→CREATE INDEX        IF NOT EXISTS idx_agent_tokens_user   ON qd_agent_tokens(user_id);
   122→CREATE INDEX        IF NOT EXISTS idx_agent_tokens_status ON qd_agent_tokens(status);
   123→
   124→-- 2. Agent async jobs (backtests / experiments / ai-optimize / ...)
   125→CREATE TABLE IF NOT EXISTS qd_agent_jobs (
   126→    id BIGSERIAL PRIMARY KEY,
   127→    job_id VARCHAR(40) NOT NULL UNIQUE,
   128→    user_id INTEGER NOT NULL REFERENCES qd_users(id) ON DELETE CASCADE,
   129→    agent_token_id INTEGER REFERENCES qd_agent_tokens(id) ON DELETE SET NULL,
   130→    kind VARCHAR(40) NOT NULL,
   131→    status VARCHAR(20) NOT NULL DEFAULT 'queued',
   132→    request JSONB NOT NULL DEFAULT '{}'::jsonb,
   133→    result JSONB,
   134→    error TEXT,
   135→    progress JSONB,                      -- NEW in V3.1.0: latest snapshot for SSE cold reconnects
   136→    idempotency_key VARCHAR(120),
   137→    created_at TIMESTAMP DEFAULT NOW(),
   138→    started_at TIMESTAMP,
   139→    finished_at TIMESTAMP
   140→);
   141→-- Safe to run even if the table existed (e.g. _ensure_schema already created
   142→-- the V3.0 shape without `progress`):
   143→ALTER TABLE qd_agent_jobs ADD COLUMN IF NOT EXISTS progress JSONB;
   144→
   145→CREATE INDEX        IF NOT EXISTS idx_agent_jobs_user   ON qd_agent_jobs(user_id);
   146→CREATE INDEX        IF NOT EXISTS idx_agent_jobs_status ON qd_agent_jobs(status);
   147→CREATE INDEX        IF NOT EXISTS idx_agent_jobs_kind   ON qd_agent_jobs(kind);
   148→CREATE UNIQUE INDEX IF NOT EXISTS idx_agent_jobs_idem
   149→    ON qd_agent_jobs(agent_token_id, kind, idempotency_key)
   150→    WHERE idempotency_key IS NOT NULL;
   151→
   152→-- 3. Append-only audit log (every agent call, including denials)
   153→CREATE TABLE IF NOT EXISTS qd_agent_audit (
   154→    id BIGSERIAL PRIMARY KEY,
   155→    user_id INTEGER NOT NULL,
   156→    agent_token_id INTEGER,
   157→    agent_name VARCHAR(80),
   158→    route VARCHAR(160) NOT NULL,
   159→    method VARCHAR(8) NOT NULL,
   160→    scope_class VARCHAR(4) NOT NULL,
   161→    status_code INTEGER NOT NULL,
   162→    idempotency_key VARCHAR(120),
   163→    request_summary JSONB,               -- redacted by _redact() before insert
   164→    response_summary JSONB,
   165→    duration_ms INTEGER,
   166→    created_at TIMESTAMP DEFAULT NOW()
   167→);
   168→CREATE INDEX IF NOT EXISTS idx_agent_audit_user  ON qd_agent_audit(user_id, created_at DESC);
   169→CREATE INDEX IF NOT EXISTS idx_agent_audit_token ON qd_agent_audit(agent_token_id, created_at DESC);
   170→CREATE INDEX IF NOT EXISTS idx_agent_audit_class ON qd_agent_audit(scope_class);
   171→
   172→-- 4. Paper-only ledger so T-class tokens can simulate without ever
   173→--    touching live exchange credentials.
   174→CREATE TABLE IF NOT EXISTS qd_agent_paper_orders (
   175→    id BIGSERIAL PRIMARY KEY,
   176→    order_uid VARCHAR(40) NOT NULL UNIQUE,
   177→    user_id INTEGER NOT NULL REFERENCES qd_users(id) ON DELETE CASCADE,
   178→    agent_token_id INTEGER REFERENCES qd_agent_tokens(id) ON DELETE SET NULL,
   179→    market VARCHAR(40) NOT NULL,
   180→    symbol VARCHAR(60) NOT NULL,
   181→    side VARCHAR(8) NOT NULL,
   182→    order_type VARCHAR(16) NOT NULL DEFAULT 'market',
   183→    qty DECIMAL(28,10) NOT NULL,
   184→    limit_price DECIMAL(28,10),
   185→    fill_price DECIMAL(28,10),
   186→    fill_value DECIMAL(28,10),
   187→    status VARCHAR(16) NOT NULL DEFAULT 'filled',
   188→    note TEXT,
   189→    created_at TIMESTAMP DEFAULT NOW()
   190→);
   191→CREATE INDEX IF NOT EXISTS idx_agent_paper_orders_user  ON qd_agent_paper_orders(user_id, created_at DESC);
   192→CREATE INDEX IF NOT EXISTS idx_agent_paper_orders_token ON qd_agent_paper_orders(agent_token_id);
   193→
   194→DO $$ BEGIN RAISE NOTICE '✅ QuantDinger V3.1.0 agent gateway schema migration completed!'; END $$;
   195→```

   250→### ⚠️ Operational notes
   251→
   252→1. **第一次启动可以不跑 SQL**：Agent Gateway 第一次接到请求时会自动建表（`_ensure_schema`）。但建议升级时统一执行上面的迁移以保证索引齐全。
   253→2. **实盘开关默认关**：`AGENT_LIVE_TRADING_ENABLED` 不设或非 `true`，T 类 token 即便配置了 `paper_only=false` 也只走 `qd_agent_paper_orders`。这是产品级红线，请勿在文档/代码里弱化。
   254→3. **签发的 token 不可恢复**：库里只存 SHA-256 hash，前端 reveal 弹窗关掉就找不回了，丢了只能撤销重签。
   255→4. **MCP HTTP 模式生产部署**：`streamable-http` 默认 bind 到 `127.0.0.1`，对外暴露请显式设 `QUANTDINGER_MCP_HOST=0.0.0.0` 并放到 nginx / 反代后面，**只让带 Agent token 的客户端访问**。

   307→## V3.0.2 (2026-04-11) — 交易机器人全链路修复(Grid / Martingale / Trend / DCA)
   308→
   309→### 🐛 Bug Fixes — 交易机器人
   310→
   311→针对四类机器人(网格 / 马丁 / 趋势 / 定投)做了从前端配置、脚本模板、后端执行到列表/详情页数据的端到端审计与修复:
   312→
   313→- **[P0-1] 编辑机器人会清空运行时状态**:`StrategyService.update_strategy` 此前直接用 payload 里的 `trading_config` 整体替换老记录,导致 `script_runtime_state`(马丁 `layer`/`total_cost`、网格 `bp/sp/prev_price`、DCA `total_qty` 等)被一把抹掉,改完参数重启就像换了台新机器人。改为 `{**existing, **incoming}` 浅合并,并保护 `script_runtime_state`、`last_signal_time`、`last_execution_time`、`bot_runtime_stats` 等后端维护的运行时字段。
   314→- **[P0-2] 网格空头不受预算控制**:旧 `total_spent` 只在买入时累加,卖出开空(中性/做空模式)既不检查也不累加,合约下可以把空头无限放大直至爆仓。重写网格脚本改为 `long_exposure` / `short_exposure` 双路独立核算,BUY 先抵扣空头再开多(做多侧过预算就跳过),SELL 同理。
   315→- **[P0-3] 马丁/趋势默认 `maker` 限价挂单导致漏触发和重复下单**:马丁每层加仓依赖上一单「已成交」才会更新 `last_entry_price`,挂单未成交时脚本在下一根 K 线用同一价格重新发单,出现一次开仓就下两笔甚至多笔的现象。向导 `buildPayload` 对 `bot_type` 为 `martingale` / `trend` 强制 `order_mode='market'`,网格/DCA 保留用户选择(默认 maker 更省费)。
   316→- **[P0-4] 网格/DCA 在同一 tick 多笔减仓的本地持仓跟踪错误**:`_script_orders_to_execution_signals` 把脚本传来的 USDT 名义金额直接丢给 `ctx.position.reduce_position/add_position/open_position`(这些方法内部以 qty 单位计数),导致同一 tick 内若先后发 sell + sell,第二笔会被误判为「开空」而不是「继续平多」,发出错误的 `open_short` 信号。修复:把 USDT 金额按 `usdt * leverage / ref_price` 换算成近似 qty 再更新本地 ctx.position(真实下单数量依旧由 `_execute_signal` 按杠杆/市场类型重算,完全不变)。
   317→- **[P0-5] DCA 频率被 K 线周期吞掉**:`intervalBars = round(freqMin / tfMin)` 当 `freq<tf`(比如 4h 线上选 hourly)会取整到 0,再 `max(1,0)=1`,结果变成「每根 K 线都买」(等于 4 小时 1 次)。把 DCA 脚本改成 **基于真实时间戳** 的 `INTERVAL_SEC = freqMin * 60`,用 `now - last_buy_ts >= INTERVAL_SEC` 判断,彻底与 K 线周期解耦。

  1020→
  1021→#### Parameter Declaration Syntax
  1022→```
  1023→# @param <name> <type> <default> <description>
  1024→```
  1025→
  1026→| Field | Description | Example |
  1027→|-------|-------------|---------|
  1028→| name | Parameter name (variable name) | `ma_fast` |
  1029→| type | Data type: `int`, `float`, `bool`, `str` | `int` |
  1030→| default | Default value | `5` |
  1031→| description | Description (shown in UI tooltip) | `Short-term MA period` |
  1032→
  1033→#### Example: Dual Moving Average with Parameters
  1034→```python
  1035→# @param sma_short int 14 Short-term MA period
  1036→# @param sma_long int 28 Long-term MA period
  1037→
  1038→# Get parameters
  1039→sma_short_period = params.get('sma_short', 14)
  1040→sma_long_period = params.get('sma_long', 28)
  1041→
  1042→my_indicator_name = "Dual MA Strategy"
  1043→my_indicator_description = f"SMA{sma_short_period}/{sma_long_period} crossover"
  1044→
  1045→df = df.copy()
  1046→sma_short = df["close"].rolling(sma_short_period).mean()
  1047→sma_long = df["close"].rolling(sma_long_period).mean()
  1048→
  1049→# Golden cross / Death cross
  1050→buy = (sma_short > sma_long) & (sma_short.shift(1) <= sma_long.shift(1))
  1051→sell = (sma_short < sma_long) & (sma_short.shift(1) >= sma_long.shift(1))
  1052→
  1053→df["buy"] = buy.fillna(False).astype(bool)
  1054→df["sell"] = sell.fillna(False).astype(bool)
  1055→
  1056→# Chart markers
  1057→buy_marks = [df["low"].iloc[i] * 0.995 if df["buy"].iloc[i] else None for i in range(len(df))]
  1058→sell_marks = [df["high"].iloc[i] * 1.005 if df["sell"].iloc[i] else None for i in range(len(df))]
  1059→
  1060→output = {
  1061→    "name": my_indicator_name,
  1062→    "plots": [
  1063→        {"name": f"SMA{sma_short_period}", "data": sma_short.tolist(), "color": "#FF9800", "overlay": True},
  1064→        {"name": f"SMA{sma_long_period}", "data": sma_long.tolist(), "color": "#3F51B5", "overlay": True}
  1065→    ],
  1066→    "signals": [
  1067→        {"type": "buy", "text": "B", "data": buy_marks, "color": "#00E676"},
  1068→        {"type": "sell", "text": "S", "data": sell_marks, "color": "#FF5252"}
  1069→    ]
  1070→}
  1071→```
